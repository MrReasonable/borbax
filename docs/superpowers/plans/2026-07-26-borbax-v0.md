# Borbax V0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a generated chemistry that runs in a well-mixed beaker, and prove that catalysis emerges from molecular shape alone — with nothing in the code that knows what an enzyme is.

**Architecture:** A Rust workspace of small, single-purpose crates. A 64-bit seed generates a periodic table with genuine periodicity; molecules are atom graphs reduced to a canonical form, embedded in 3D, and sampled along the vertices of a subdivided icosahedron into a directional shape signature; binding is a complementarity test between two signatures searched over the 60-element icosahedral rotation group; polymers fold on an FCC lattice and expose enclosed cavities; catalysis is two cavities sitting close enough to hold two reactants together. Everything expensive is computed once per *species*, never per molecule. No world and no spatial simulation — it all runs in a single well-mixed volume so the iteration loop stays measured in seconds — but shapes are rendered to SVG from the start, because a shape-based chemistry cannot be developed blind.

**Tech Stack:** Rust 1.97.1, pinned via proto. Settled crates rather than
hand-rolling — `thiserror`, `clap`, `libm`, `serde`, `rustc-hash` at runtime;
`proptest`, `insta`, `criterion`, `rstest` for tests. Vector maths and the graph algorithms
*are* written directly — because they are small, not because a crate would
break determinism. `glam` and `nalgebra` would both be bit-identical here
(checked in their source), so this is a size judgement. Stating it as a
determinism argument would be a false doctrine that later gets used to reject
a dependency that is genuinely correct. See CLAUDE.md § Dependencies for the rule
that decides which is which: dev-dependencies are cheap, a runtime dependency
in a result-affecting path is a physics change.

**Spec:** `docs/superpowers/specs/2026-07-26-borbax-prd.md`. V0 exit criteria are §23.

## Global Constraints

These apply to every task. A task's requirements implicitly include this section.

- **Rust 1.97.1**, pinned in `.prototools`. Never bump without regenerating golden hashes (spec §18.1).
- **Determinism is a hard requirement.** Same seed → bit-identical output, always. No `HashMap` iteration in any code path that affects results (use `BTreeMap`, or sort before iterating). No wall-clock. No thread-scheduling-dependent reduction order. No `f32`; all simulation arithmetic is `f64`.
- **All randomness comes from `borbax_rng::Stream`.** Never `rand::random`, never a thread-local RNG, never `std::collections::hash_map::RandomState`.
- **No real chemistry data anywhere** (spec §5, G1). No element tables, no reaction databases, no molecular structures. CI enforces this.
- **No real-world units** (G4). Temperature is `Thermal`, energy is `Quanta`, distance is `Span`, time is `WorldYear`, mass is `Mass`. These are distinct newtypes and the compiler enforces they do not mix.
- **Every reaction conserves mass.** Products' total mass equals reactants' total mass, exactly, checked in tests.
- **No `unwrap()` or `expect()` in library code.** Return `Result` or `Option`. Tests may unwrap freely.
- **Commit after every task.** Conventional commits (`feat:`, `test:`, `fix:`, `chore:`, `docs:`).
- **Every commit message ends with the trailer:** `MrReasonable <4990954+MrReasonable@users.noreply.github.com>`

`borbax-geometry` computes what to draw; `borbax-render` turns that into SVG. V1's
`borbax-ui` will be a second backend over the same geometry (spec §14.5), which is
why the split exists this early rather than being introduced later.

**No TypeScript, Node or pnpm** — the native-viewer decision (spec §14.0) removed
the entire JavaScript toolchain from the project. One language, one build, one
test command.

Each crate has one responsibility and can be understood without reading its neighbours. `borbax-molecule` carries the conceptual weight of the project and is deliberately split into small files — most iteration will happen there.

**`det_math` is in `borbax-units` deliberately, and must stay there.** It is
called from `borbax-rng`'s normal-variate draw and `borbax-universe`'s mass
generation, both of which sit *below* `borbax-molecule` in the crate order. Put
it any higher and the one file that exists to guarantee portability is
unreachable from two of the crates that need it, with the only escape being a
dependency edge that inverts the whole ordering. `borbax-units` has no
dependencies of its own, so it is the one place every crate can reach.

```rust
//! Fiction-guarantee enforcement (spec §5). Run in CI.
//!
//! These checks make "no real chemistry" an architectural property rather
//! than a promise. They are cheap and they run on every commit.

use std::path::{Path, PathBuf};

/// Extensions that would indicate bulk data smuggled into a chemistry crate.
/// The entire chemistry is generated from a seed; there is nothing legitimate
/// for a data file to be doing in these crates.
const DATA_EXTENSIONS: &[&str] = &["csv", "tsv", "json", "yaml", "yml", "parquet", "bin", "dat"];

/// Crates that must contain no data files at all (G1).
const CHEMISTRY_CRATES: &[&str] = &[
    "crates/borbax-universe",
    "crates/borbax-molecule",
    "crates/borbax-reaction",
];

/// Real chemical-format tokens that must never appear anywhere (G5).
const FORBIDDEN_FORMAT_TOKENS: &[&str] = &["SMILES", "InChI", "FASTA", "PDB format"];

fn main() -> Result<(), String> {
    let root = PathBuf::from(env!("CARGO_MANIFEST_DIR"))
        .parent()
        .ok_or("no workspace root")?
        .to_path_buf();

    let mut failures = Vec::new();
    check_no_data_files(&root, &mut failures)?;
    check_blocklist_present(&root, &mut failures)?;

    if failures.is_empty() {
        println!("fiction guarantees: all checks passed");
        Ok(())
    } else {
        for f in &failures {
            eprintln!("FAIL: {f}");
        }
        Err(format!(
            "{} fiction-guarantee check(s) failed",
            failures.len()
        ))
    }
}

/// G1 — no real chemistry data enters the repository.
fn check_no_data_files(root: &Path, failures: &mut Vec<String>) -> Result<(), String> {
    for krate in CHEMISTRY_CRATES {
        let dir = root.join(krate);
        if !dir.exists() {
            continue;
        }
        for entry in walk(&dir)? {
            let Some(ext) = entry.extension().and_then(|e| e.to_str()) else {
                continue;
            };
            if DATA_EXTENSIONS.contains(&ext) {
                failures.push(format!(
                    "G1: data file in chemistry crate: {}",
                    entry.display()
                ));
            }
        }
    }
    Ok(())
}

/// G2 — the blocklist must exist and be non-trivial, or name generation
/// is unguarded and could mint a real element symbol.
fn check_blocklist_present(root: &Path, failures: &mut Vec<String>) -> Result<(), String> {
    let path = root.join("crates/borbax-universe/src/naming.rs");
    if !path.exists() {
        // Not yet written — Task 4 creates it. Not a failure before then.
        return Ok(());
    }
    let src = std::fs::read_to_string(&path).map_err(|e| e.to_string())?;
    if !src.contains("REAL_ELEMENT_SYMBOLS") {
        failures.push("G2: naming.rs has no REAL_ELEMENT_SYMBOLS blocklist".into());
    }
    for token in FORBIDDEN_FORMAT_TOKENS {
        if src.contains(token) {
            failures.push(format!("G5: forbidden format token {token:?} in naming.rs"));
        }
    }
    Ok(())
}

fn walk(dir: &Path) -> Result<Vec<PathBuf>, String> {
    let mut out = Vec::new();
    let mut stack = vec![dir.to_path_buf()];
    while let Some(d) = stack.pop() {
        for entry in std::fs::read_dir(&d).map_err(|e| e.to_string())? {
            let path = entry.map_err(|e| e.to_string())?.path();
            if path.is_dir() {
                if path.file_name().and_then(|n| n.to_str()) != Some("target") {
                    stack.push(path);
                }
            } else {
                out.push(path);
            }
        }
    }
    // Sort so failures are reported in a stable order.
    out.sort();
    Ok(out)
}
```

- [x] **Step 6: Add CI**

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]

jobs:
  # The matrix is not for coverage — it is the enforcement mechanism for the
  # cross-platform determinism promise in spec §13.4. Every portability
  # hazard listed there is invisible on a single machine: the code runs, the
  # tests pass, the numbers look fine, and the failure only appears when
  # someone opens a shared seed on different hardware. Running goldens on
  # one platform would pass happily while the promise quietly rotted.
  test:
    name: test (${{ matrix.os }})
    runs-on: ${{ matrix.os }}
    strategy:
      fail-fast: false
      matrix:
        os: [macos-latest, ubuntu-latest, windows-latest]
    steps:
      - uses: actions/checkout@v5
      - uses: moonrepo/setup-toolchain@v0
        with:
          auto-install: true
      - name: Fiction guarantees (spec §5)
        run: cargo run -p xtask
      - name: Format
        run: cargo fmt --all --check
      - name: Clippy
        run: cargo clippy --workspace --all-targets -- -D warnings
      - name: Test
        run: cargo test --workspace
      # borbax-cli does not exist until Task 21. Without this guard the whole
      # `test` job fails on all three platforms for twenty tasks — and because
      # `determinism-matrix` is gated on `needs: test`, it would never run at
      # all. Its inertness would be accidental rather than designed, which is
      # the opposite of what §13.6 needs.
      #
      # `shell: bash` is load-bearing, not tidiness. The Windows leg would
      # otherwise run under pwsh, whose redirection operator rewrites the
      # stream with native CRLF line endings — so `diff -u` in
      # `determinism-matrix` would report a divergence on the very first
      # golden run, for a reason that has nothing to do with the simulation.
      # A determinism gate that cries wolf once gets muted forever.
      - name: Emit golden hashes
        if: hashFiles('crates/borbax-cli/Cargo.toml') != ''
        shell: bash
        run: cargo run -p borbax-cli --release -- goldens --emit > goldens-${{ matrix.os }}.txt
      - uses: actions/upload-artifact@v4
        if: hashFiles('crates/borbax-cli/Cargo.toml') != ''
        with:
          name: goldens-${{ matrix.os }}
          path: goldens-${{ matrix.os }}.txt

  # The actual cross-platform assertion. Task 1 creates the job with a
  # placeholder step; it becomes real once borbax-cli exists (Task 20).
  determinism-matrix:
    name: goldens identical across platforms
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/download-artifact@v4
      - name: Compare golden hashes across platforms
        shell: bash
        run: |
          set -euo pipefail
          shopt -s nullglob
          files=(goldens-*/goldens-*.txt)
          if [ ${#files[@]} -eq 0 ]; then
            echo "No golden artifacts yet (expected before Task 20)."
            exit 0
          fi
          ref="${files[0]}"
          fail=0
          for f in "${files[@]:1}"; do
            if ! diff -u "$ref" "$f"; then
              echo "DETERMINISM FAILURE: $f differs from $ref"
              fail=1
            fi
          done
          [ $fail -eq 0 ] && echo "goldens identical across ${#files[@]} platforms"
          exit $fail
```

Note `macos-latest` is aarch64 and the other two are x86-64, so the matrix
covers both architectures as well as all three operating systems.

**The golden state hash has to be specified, not assumed.** It is the mechanism
the whole §13.6 contract rests on, and "emit a hash" is not a specification.
Task 21 implements it to this shape:

- a fixed list of seeds and checkpoint step counts, committed alongside the code
- species emitted in `SpeciesId` order — never map order
- counts as `borbax_units::canonical_bits`, `Mass` as `canonical_bits()`, time as `canonical_bits` — **not** `f64::to_bits`, which leaves the architecture-dependent NaN sign and the `-0.0`/`0.0` distinction in the hash. Assert finiteness at this boundary as well: canonicalising is belt-and-braces, and on its own it would turn a genuine NaN divergence into a green matrix
- fed to a fixed digest, never `DefaultHasher` (whose output is not stable
  across Rust releases)

Both the ordering and the bit-exact float encoding are load-bearing. A hash that
formats floats as decimal strings would hide exactly the divergences this exists
to catch.

**Interfaces:**

- Produces: `Thermal(f64)`, `Quanta(f64)`, `Span(f64)`, `WorldYear(f64)`, `Mass(f64)` — each with `Add`, `Sub`, `Mul<f64>`, `Div<f64>`, `PartialOrd`, `Sum`. `Quanta::ZERO`, `Mass::ZERO`. No cross-unit arithmetic compiles.

**As built — six deviations, all found by executing or reviewing the task.
Later tasks should follow the code, not the text below.**

1. **`Mass` has no `Mul<f64>` and cannot hold a float**, so Step 1's
   `scales_by_scalar` and `sums_over_iterator` tests — written against
   `Mass(2.0)` — cannot compile against Step 3's own implementation. Scaling
   moved to `Span`; `Mass` gained tests for the property it exists for
   (exact conservation under reordering).

```rust
//! Invented units (spec §5, G4).
//!
//! Borbax never uses real-world units. Temperature is measured in thermals,
//! energy in quanta, distance in spans, time in world-years, mass in mass
//! units defined by the generated periodic table. These are distinct types
//! and the compiler refuses to mix them — which is the point. It prevents
//! anyone, including us, from quietly reasoning about the simulation as
//! though it modelled something real.

use std::iter::Sum;
use std::ops::{Add, AddAssign, Div, Mul, Neg, Sub};

macro_rules! unit {
    ($name:ident, $doc:literal) => {
        #[doc = $doc]
        // repr(transparent) guarantees `[Quanta; 8]` is layout-compatible
        // with `[f64; 8]`. Without it we would be relying on unspecified
        // repr(Rust) behaviour that merely happens to work today, and the
        // signature kernel depends on that layout to vectorise.
        #[repr(transparent)]
        #[derive(Debug, Clone, Copy, PartialEq, PartialOrd, Default)]
        pub struct $name(pub f64);

        impl $name {
            pub const ZERO: Self = Self(0.0);

            #[must_use]
            pub fn get(self) -> f64 {
                self.0
            }

            #[must_use]
            pub fn is_finite(self) -> bool {
                self.0.is_finite()
            }
        }

        impl Add for $name {
            type Output = Self;
            fn add(self, rhs: Self) -> Self {
                Self(self.0 + rhs.0)
            }
        }

        impl AddAssign for $name {
            fn add_assign(&mut self, rhs: Self) {
                self.0 += rhs.0;
            }
        }

        impl Sub for $name {
            type Output = Self;
            fn sub(self, rhs: Self) -> Self {
                Self(self.0 - rhs.0)
            }
        }

        impl Neg for $name {
            type Output = Self;
            fn neg(self) -> Self {
                Self(-self.0)
            }
        }

        /// Scaling by a dimensionless scalar is allowed; multiplying two
        /// quantities of the same unit is not, because the result would
        /// have a unit we have no name for.
        impl Mul<f64> for $name {
            type Output = Self;
            fn mul(self, rhs: f64) -> Self {
                Self(self.0 * rhs)
            }
        }

        impl Div<f64> for $name {
            type Output = Self;
            fn div(self, rhs: f64) -> Self {
                Self(self.0 / rhs)
            }
        }

        /// Dividing like by like yields a dimensionless ratio.
        impl Div for $name {
            type Output = f64;
            fn div(self, rhs: Self) -> f64 {
                self.0 / rhs.0
            }
        }

        impl Sum for $name {
            fn sum<I: Iterator<Item = Self>>(iter: I) -> Self {
                iter.fold(Self::ZERO, Add::add)
            }
        }
    };
}

unit!(Thermal, "Temperature, in thermals. Not Kelvin, not Celsius.");
unit!(Quanta, "Energy, in quanta. Not joules.");
unit!(Span, "Distance, in spans. Not metres.");
unit!(WorldYear, "Time, in world-years — defined by the generated world's own orbit.");

/// Mass, in mass units defined by the generated periodic table.
///
/// **Fixed-point, not floating-point** — deliberately the odd one out.
///
/// The global constraints require that a reaction's products have *exactly*
/// the mass of its reactants. Naive `f64` summation over many terms cannot
/// deliver that: you get a tolerance argument instead of a guarantee, and
/// the tolerance has to grow as molecules get larger. Integer arithmetic
/// makes conservation exact by construction, so the test is `==` rather
/// than `(a - b).abs() < eps` — and it stays exact on every platform,
/// which matters for spec §13.4.
///
/// The representation is 1/1024 of a nominal mass unit. Generated atomic
/// masses are quantised onto this grid once, at universe-generation time,
/// so every molecular mass is an exact sum of exact atomic masses forever
/// after.
#[repr(transparent)]
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash, Default)]
pub struct Mass(i64);

impl Mass {
    /// Sub-units per mass unit. A power of two so that quantisation is
    /// exact in binary and the grid has no representation error of its own.
    pub const SCALE: i64 = 1024;
    pub const ZERO: Self = Self(0);

    /// Quantise a real value onto the fixed-point grid.
    ///
    /// Called only at universe-generation time, never in a hot path.
    /// `round_ties_even` is used rather than `round` because it is
    /// symmetric — `round` biases away from zero, which would make
    /// generated mass distributions very slightly heavier than intended.
    #[must_use]
    pub fn from_f64_quantised(v: f64) -> Self {
        Self((v * Self::SCALE as f64).round_ties_even() as i64)
    }

    /// Approximate real value, for display and for rate arithmetic.
    /// Never round-trip through this to perform a conservation check —
    /// compare `Mass` values directly.
    #[must_use]
    pub fn to_f64(self) -> f64 {
        self.0 as f64 / Self::SCALE as f64
    }

    #[must_use]
    pub const fn raw(self) -> i64 {
        self.0
    }

    #[must_use]
    pub const fn from_raw(v: i64) -> Self {
        Self(v)
    }

    /// Scale by a whole number of copies — stoichiometry. Returns `None`
    /// on overflow rather than wrapping, because a silently wrapped mass
    /// would look like a conservation violation somewhere far away.
    #[must_use]
    pub fn checked_mul_count(self, n: u32) -> Option<Self> {
        self.0.checked_mul(i64::from(n)).map(Self)
    }
}

impl Add for Mass {
    type Output = Self;
    fn add(self, rhs: Self) -> Self {
        Self(self.0 + rhs.0)
    }
}

impl AddAssign for Mass {
    fn add_assign(&mut self, rhs: Self) {
        self.0 += rhs.0;
    }
}

impl Sub for Mass {
    type Output = Self;
    fn sub(self, rhs: Self) -> Self {
        Self(self.0 - rhs.0)
    }
}

impl Neg for Mass {
    type Output = Self;
    fn neg(self) -> Self {
        Self(-self.0)
    }
}

impl Sum for Mass {
    fn sum<I: Iterator<Item = Self>>(iter: I) -> Self {
        iter.fold(Self::ZERO, Add::add)
    }
}
```

**Canonical summation shape — decide it here, once.**

`Sum` above folds left, serially. That is a dependency chain of `fadd`s for
the float units and LLVM will not reassociate floats to break it, so it is
not the fastest possible summation. Using multiple accumulators would be
faster and would produce **different bits**.

The decision is: **left fold, serial, everywhere.** It is the obvious
reading, it is what a reviewer expects, and the alternative buys throughput
in a place that is not the bottleneck (§8.6 — the hot loop reads precomputed
per-species records, it does not sum long lists). Retrofitting a different
shape later moves every golden hash in the workspace, which is why it is
being nailed down before the first golden exists rather than after.

Note this concern does not apply to `Mass` at all — integer addition is
associative and exact, so accumulator strategy cannot change its result.
That is a second, quieter argument for the fixed-point choice.

```rust
//! Portable transcendentals (spec §13.1, §13.4).
//!
//! Backed by the `libm` crate — rust-lang's pure-Rust port of MUSL's libm,
//! with no platform dispatch. Apple's libm and glibc genuinely disagree in the
//! last bits of `exp`, `ln`, `sin` and `cos`, and glibc versions disagree with
//! each other. None of them is wrong: IEEE-754 does not specify these to be
//! correctly rounded. It only specifies `+ - * / sqrt`, which is why those stay
//! native.
//!
//! **This lives in `borbax-units` because it must sit below every caller.**
//! `borbax-rng` and `borbax-universe` both need it and both sit below
//! `borbax-molecule`; anywhere higher and this file is unreachable from two of
//! the crates it exists to serve.
//!
//! A direct `.exp()` or `.cos()` on an `f64` anywhere in library code is a
//! determinism bug. There is a CI check for it in `xtask`.

/// `e^x`.
#[must_use]
pub fn exp(x: f64) -> f64 {
    libm::exp(x)
}

/// Natural logarithm. Callers must guarantee `x > 0` — `ln(0)` is `-inf` and
/// will silently poison whatever consumes it (see Task 18's clock).
#[must_use]
pub fn ln(x: f64) -> f64 {
    libm::log(x)
}

#[must_use]
pub fn sin(x: f64) -> f64 {
    libm::sin(x)
}

#[must_use]
pub fn cos(x: f64) -> f64 {
    libm::cos(x)
}

/// `x^y` for runtime `y`. For small integer exponents write the multiplication
/// out instead: `powi`'s multiply tree is chosen by LLVM, so it can be
/// re-associated by a compiler upgrade without our source changing.
#[must_use]
pub fn powf(x: f64, y: f64) -> f64 {
    libm::pow(x, y)
}
```

- [x] **Step 7: Add the xtask check that nothing bypasses it**

Extend `xtask` with a scan for direct transcendental calls in library code.
This is the check that stops the chokepoint being quietly bypassed six months
from now, and it is cheap:

```rust
/// §13.1 — every transcendental must route through `borbax_units::det_math`.
/// A direct call is invisible locally and only diverges on another platform,
/// so a grep at commit time is worth more than a code review.
const BANNED_CALLS: &[&str] =
    &[".exp()", ".ln()", ".log(", ".sin()", ".cos()", ".tan()", ".powf(", ".powi("];

/// The one file allowed to call the platform, identified by its *path*.
///
/// Matching on the filename alone would exempt a `det_math.rs` anywhere in the
/// tree, which is the precise bypass this check exists to prevent: a second
/// copy in whichever crate happened to need one is how the chokepoint stops
/// being a chokepoint. There is exactly one, it is in `borbax-units` because
/// two crates below `borbax-molecule` call it (spec §18.3), and moving it is a
/// deliberate change to this constant rather than a silently-tolerated
/// duplicate.
const DET_MATH_PATH: &str = "crates/borbax-units/src/det_math.rs";

fn check_no_platform_transcendentals(root: &Path, failures: &mut Vec<String>) -> Result<(), String> {
    let crates_dir = root.join("crates");
    if !crates_dir.exists() {
        return Ok(());
    }
    // Scanned wholesale rather than from a list of crate names. A hand-kept
    // list silently exempts every crate added after it was written, which is
    // the same failure mode as the filename exemption above.
    for entry in walk(&crates_dir)? {
        if entry.extension().and_then(|e| e.to_str()) != Some("rs") {
            continue;
        }
        // Component-wise comparison against the workspace-relative path.
        // `Path` treats `/` as a separator on Windows too, so the literal
        // above is portable.
        let rel = entry.strip_prefix(root).unwrap_or(&entry);
        if rel == Path::new(DET_MATH_PATH) {
            continue;
        }
        let src = std::fs::read_to_string(&entry).map_err(|e| e.to_string())?;
        for (i, line) in src.lines().enumerate() {
            // Test modules may use anything.
            if line.trim_start().starts_with("//") {
                continue;
            }
            for call in BANNED_CALLS {
                if line.contains(call) {
                    failures.push(format!(
                        "§13.1: platform transcendental {call} at {}:{} — route through det_math",
                        entry.display(),
                        i + 1
                    ));
                }
            }
        }
    }
    Ok(())
}
```

test, because it is part of the determinism contract from that moment.

```rust
//! Counter-based deterministic randomness (spec §13.1).
//!
//! Every random draw in Borbax comes from here. Streams are *counter-based*
//! rather than stateful-shared: a stream's output is a pure function of
//! (seed, domain, index, counter), so two threads drawing from different
//! streams cannot influence each other and results never depend on
//! scheduling order. That property is what makes bit-for-bit reproducibility
//! survive parallelism.
//!
//! Never use `rand`, thread-local RNGs, or `HashMap`'s default hasher in
//! any code path that affects simulation results.

/// Which subsystem a stream belongs to. Streams in different domains are
/// independent, so adding a new random draw in one subsystem cannot shift
/// the sequence any other subsystem sees — which means a change to folding
/// does not silently perturb reaction outcomes.
#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]
#[repr(u64)]
pub enum Domain {
    Universe = 1,
    Naming = 2,
    Molecule = 3,
    Fold = 4,
    Reaction = 5,
    Decay = 6,
    Beaker = 7,
    Shadow = 8,
    /// Hashing only — cache keys and content digests. Separated from the live
    /// domains so that using a `Stream` as a hash function cannot couple to
    /// the subsystem it names: adding a draw in folding must not change fold
    /// cache keys.
    Hash = 9,
}
```

**Discriminants are explicit and permanent, and a new variant may only be
appended.** This is the seam that lets physics be extended later without
invalidating every world already generated, and it costs nothing to establish
now.

`Stream::new` derives its key from `(seed, domain, index)`, so streams are
independent by construction: a draw taken from `Domain::Fold` cannot shift a
draw from `Domain::Universe`. The `Hash` variant above already relies on this
for a smaller reason. Generalised, it means **a V3 law whose constants come
from a new `Domain = 10` leaves every constant an existing universe already
generated bit-identical** — the periodic table, the bond matrix, the binding
weights, all unchanged.

Without that discipline the alternative is grim: adding a single
`rng.next_f64()` to universe generation shifts every subsequent draw in that
stream, so every existing seed silently generates a *different* periodic table.
Worlds shared as `U-7F3A21C9` would stop meaning what they meant (§6), and
nothing would announce it.

Two rules follow, and both are cheap:

1. **Append; never renumber, never reuse.** A removed subsystem's discriminant
   is retired, not recycled. Reordering the enum is a physics change.
2. **New physics draws from a new `Domain`.** Reaching into an existing one to
   add "just one more constant" is the mistake this enum exists to prevent.

#### What the table is

**Element `N` is `N` copies of one base unit, packed.** Nothing about an element
is drawn from a curve chosen because it looked plausible: mass, radius, valence,
affinity, `decay_rate` and `abundance` are all functions of how `N` units pack.

fitted shape per property: mass as `base·(i+1)^growth + noise`, valence as a
triangular function of position across a period, radius and affinity as trends

lengths. Every property is then a shape someone picked, and nothing causes
anything. That is principle 2 — nothing hardcoded that could fall out of a
mechanism — violated in the file that defines what an atom is.

| property | fitted curve | derived from packing |
|---|---|---|
| mass | `base·(i+1)^growth + noise` | `N × base_mass − contacts(N) × contact_defect` |

#### Where the invention lives, and the G3 position

The `n`th shell holds **`k·n² + 2`** units. Only `k` is drawn.

The `n²` is geometry: a shell is a surface and a surface grows as the square of
its radius. The `+ 2` is the **Euler characteristic** — for a convex simplicial
polyhedron the shell count reduces to `(F/2)n² + 2` via `3F = 2E` and
`V − E + F = 2`, which also forces `k = V − 2` and hence `z = k + 2`. It is not
"the antipodal pair every shell carries", as a draft said: the tetrahedron has
`k = 2`, shell 1 = 4, and no antipodal vertex pair at all. `k` is how
densely the base unit's own shape lets neighbours tile that surface — a property
of the generated unit, and the thing that makes two universes differ in table
*shape* rather than only in their numbers. Measured over `k ∈ 6..=14`, the
closure sets inside a 120-element table are all distinct:

```
  k     closures within 120        k     closures within 120
  6     [1,  9, 35,  91]          11     [1, 14, 60]
  7     [1, 10, 40, 105]          12     [1, 15, 65]
  8     [1, 11, 45, 119]          13     [1, 16, 70]
  9     [1, 12, 50]               14     [1, 17, 75]
 10     [1, 13, 55]
```

**`k = 10` gives `10n² + 2` = 12, 42, 92 — the shell populations of the Mackay
icosahedral packing.** The magic numbers seen experimentally are the
*cumulative* sizes 13, 55, 147, **not** these; an earlier version of this
paragraph attached the observation to the shell populations, swapping the two
quantities it otherwise distinguishes.

**It is not corroboration.** `10n² + 2` is the vertex count of the nth
icosahedral geodesic subdivision, forced by Euler with twelve five-fold
vertices — the same formula generating this project's own `D ∈ {12, 42, 162}`.
The shell law re-derives a consequence of `χ = 2` the codebase needed anyway.
The G3 position is that `k` spans a family of nine, nothing may bias the draw
toward 10 on account of the coincidence, and no claim depends on the
experiment — while the *periodic
table* it produces remains structurally unlike a real one: real periods are 2,

claim more.

#### The three mechanisms, and what each one must satisfy

**1. Valence is unmade contacts, counted over sites.**

A **contact** is an adjacency between occupied sites; an **unmade** contact is an
adjacency to an empty one. A contact is the same relation a bond is, which is
why counting contacts is causal where counting sites is numerology.

The canonical filling order is a compact spherical cap growing from one pole, so
the frontier of a partly-filled shell is a circle of latitude:

```
notches(cap, outer) = C · √(cap·f(1−f)) / z_lat(cap),   f = outer/cap
z_lat(cap)          = 6 − 12/cap                        (Euler: 3v − 6 edges)
C                   ≈ 7.30                              (see below)
```

**`C` is fitted to exact counts on real triangulated spheres, not derived — and
that is the single most important correction in this task.** The derivation
gives `6√π = 10.635`, and it is wrong by 1.46× for two compounding reasons,
neither of which any test in the probe could see, because every test compared
the formula against itself:

- *"each boundary site points three of its six contacts outward"* is **two of
  six**. Measured on triangulated spheres at V = 162, 642, 2562, unmade contacts
  per boundary site converges to exactly 2.000.
- *site spacing `√(4π/cap)`* treats area-per-site as `s²`. On a triangular
  lattice it is `(√3/2)s²`, so the spacing was 7.5% low.

Least-squares against exact counts gives 7.29 / 7.33 / 7.32 at those three
resolutions, and an independent bond-cutting derivation gives 7.275.

**So the specification is the ground truth, not the formula.** `fusion.rs` builds
a real geodesic sphere, derives its adjacency, checks the degree histogram
against Euler's twelve pentagons, fills in spherical-cap order and counts
filled-to-empty edges exactly. Task 4 must carry the same test. Without it the
constant is answerable only to the arithmetic that was wrong.

**The bound on small patches must be the *compact* one.** At `outer = 1` the
continuum returns more contacts than a single site has. Harborth's
`⌊3a − √(12a−3)⌋` is the **maximum** internal bonds over all arrangements of `a`
triangular-lattice cells, attained by the compact ones — so `6a` less twice it
is a **lower** bound on exposure, with equality only when the patch is
maximally compact. An earlier version of this paragraph said "at least ... so it
exposes at most", which inverts it; `compact_bound`'s own doc names that as the
earlier error while this sentence kept making it 800 lines away. Falsified
concretely: on a `Geodesic<162>` filled in cap order, `a = 3` exposes 14 against
a bound of 12.

An earlier version also used a bare `6a` — the bound for a patch whose sites
touch *nothing*, the opposite of the compactness the continuum assumes. Its
stated symptom, "returned valence 3 where the exact count gives 2 at
`outer = 3`", was true at the naive 10.635 and is **stale at 6.90**, where that
case is unreachable. Do not restore it as evidence.

*Why this replaces the old formula.* `sqrt(min(outer, cap−outer))` clamped at 6
was a fitted curve, and the clamp was not the only ceiling: a **per-site** count
cannot exceed `z − 6` at all. Summing over the frontier removes that ceiling in
principle, and measured, valence 9 appears once a fourth shell opens past
N = 200.

**But nothing this scheme generates gets there.** Over the drawn table size the
ceiling is **4 to 6**, and an assertion that valence reaches 8 fails on roughly
half of all seed sets.

**That is not a shortfall, and an earlier version of this task apologised for
it.** §7.2 asks for "a thin high-valence tail" — a claim about *shape*, not
magnitude. Measured, abundance at valence ≥ 3 spans 0.077 to 0.566 across
universes (median ~0.32), and at valence ≥ 4 it spans 0.018 to 0.315. **The
shape §7.2 asked for is present in every universe.** No result in the cited
literature makes maximum valence a predictor of anything: RBN-World's low-level
battery has no valence test at all, and the failure mode it names is the
opposite — "if every molecule can bond with every other molecule, the chemistry
is trivial", which is §7.2's own gel ceiling reached independently.

The residual concern is the *other* end. Two of 24 universes put only ~8–12% of
abundance at valence ≥ 3, and one of those has the thinnest Molloy–Reed margin.
Those are the near-chains-only universes, and whether valence-2 chains fold to
enclosed cavities is §8.4/§8.5 and Task 20's battery. Accept the deferral; drop
the apology.

*The guarantee is a source check, and both behavioural candidates were tried
and failed.* Zero-at-closure is held by two independent
factors — the `f(1−f)` and the compact bound — so mutating either alone leaves a
zero-at-closure assertion passing, and the deletion argument cannot separate
them. Continuity was the proposed replacement and **it was defeated**: a review
built a load-bearing `if outer == 0` returning a floored value, and it passed
every test in both files while producing a bit-identical table. Continuity is
structurally blind here because both neighbours of a closure are pinned at
valence 1, so any declaration writing 0 sits within the bound — and in the case
the plan cared about it actively *rewards* the branch.

**The claim is a property of the source, so test the source.** `xtask` already
greps Rust. A check denying `outer == 0`, `outer == cap` and `is_closed` inside
`packing.rs`'s frontier path tests exactly what is being claimed; keep the
continuity assertion as a cheap behavioural backstop, but do not present it as
the guarantee.

*The family §7.1 asks for.* Position in a drawn period caused nothing. Here, the
element one unit past **any** closure is a closed core plus a single adhering
unit, which has all its lateral contacts unmade wherever it sits — so exactly one
docking notch, in every shell of every universe. Verified for all `k ∈ 6..=14`
at every closure. That is "everything in this column behaves alike" with a cause
behind it.

**2. `peak` is an output. `derive_table` must not take a `peak` parameter.**

The old code took `peak`, computed instability as `((N − peak)/peak)²`, and
reported the resulting minimum as an emergent result. It was the distance from a
typed-in constant: setting the open-shell bonus to zero moved the minimum to
exactly `peak`, and sweeping `peak` over 5..120 landed it on a closure in 13 of
24 draws. Mass defect and instability were also two unlinked encodings of
"closed shells bind better", in incommensurable units, so neither could check
the other.

One binding energy per unit, and both are functions of it:

```
E_per_unit(N) = eps · contacts(N)/N  −  sigma · N^(2/3)
mass(N)       = N · base_mass  −  quantise(contacts(N) · contact_defect)
```

*Contacts must be accumulated shell by shell, not estimated.* The obvious
continuum form — `z·N/2` less a surface deficit growing as `N^(2/3)` — has the
deficit exceeding `N` itself for everything below `N = 113`, so it collapses to
`z·N/4`, makes contacts-per-unit a **constant**, and puts the peak at `N = 1` in
all 24 universes. That was the first run's result and it looked plausible on the
printout. Each shell's sites make inward contacts to the shell below and lateral
contacts to their own neighbours, and the inward budget is whatever outward
capacity the shell below has left. That recursion is what makes
contacts-per-unit *rise* toward `z/2`, which is what a peak needs.

*The destabiliser, and the exponent is chosen rather than derived — say so.*
A lattice cannot tile a sphere, so each shell is stretched over a larger radius
than the one below and carries strain. The code writes `sigma · N^(2/3)`.

**The stated derivation does not produce that exponent, and two reviewers got
two different answers executing it.** Taking "strain per shell grows as `n²`"
literally and summing gives per-unit strain `Σn²/N ≈ 1/k`, a *constant* — one
lens measured exactly that, converging on `1/k`. Fitting the accumulated series
over the drawn range instead gives 0.645–0.742, k-dependent. Neither is 2/3.
Reaching `N^(5/3)` total needs per-*site* strain `∝ n²`, which the comment never
states and which is the one free assumption that lands on 2/3.

Two consequences to write down rather than hide:

- **2/3 is not optimal for what this task wants.** Swept over the full drawn
  product, the fraction of universes whose peak is interior rises monotonically
  with the exponent: 28.9% at 0, 77.9% at 0.60, 85.5% at 2/3, 93.1% at 0.75,
  99.5% at 1.0. Every value from 0.60 up works and 0.75+ is strictly better.
- **`strain(1) = sigma`**, so a lone base unit carries a penalty when it has no
  shell above the core and cannot be strained — and N = 1 holds the largest
  single abundance share in the table. A shell-by-shell accumulation gives 0
  there for free.

**On G3.** The concern is real and the answer is that this is *not* a breach:
no coefficient enters the repository, `sigma` and `eps` are both drawn, no
calibration target exists, and building a transfer function would need both a
mass scale and a `sigma:eps` ratio that nothing constrains. A saturating
cohesive term against a super-extensive penalty yields a maximum; that is a
property of the functional-form class, not a published result.

**But do not defend it the way a draft did** — "no charge, no isospin, no
pairing, no asymmetry term" enumerates *absent* terms and says nothing about the
one that is present, so by that logic adding a term would make it more of a
breach. Same shape as the `libm` correction in CLAUDE.md: right conclusion,
wrong reason, and the wrong reason is what waves through the next case.

The remedy is not to change the exponent to dodge a resemblance. It is to
accumulate the strain shell-by-shell exactly as `contacts_upto` accumulates
contacts — **this task already knows a closed-form asymptotic is invalid at
these table sizes**, having abandoned one for the cohesive term after it put the
peak at N = 1 in all 24 universes, and kept one for the destabiliser. Then the
exponent stops being typed, becomes a function of `k`, and `strain(1) = 0`
falls out. Until that is done the comment must say the exponent is chosen.

*The sawtooth is structural; "the peak is always at a closure" is not.* A closed
shell has no frontier, so it makes every lateral contact available to it and
maximises contacts per unit — every closure is a **local** maximum, with zero
failures across the full `(k, eps, sigma)` product inside the drawn range. But
the **global** maximum of a series truncated mid-shell can sit at the table
edge, and measured over the drawn table size it does in 4 of 24 universes —
plus one more, seed 21, which peaks mid-shell at N = 41 with closure 75 present
in the table and not chosen. An earlier version of this sentence named two
cases and accounted for the third by miscounting the second.

Both errors have now been made here in opposite directions: the first probe
reported this as a coincidence rate and was wrong, and the correction called it
structural without qualification and was also wrong. The accurate statement is
that the sawtooth is a mechanism and the argmax over a truncated series is not.
It matters because `decay_rate` is the distance below the peak, so in a universe
where the peak is the table edge every element's decay is anchored to an
arbitrary boundary — and
`energy_per_unit_is_locally_maximal_at_every_closure` still passes, because it
tests the sawtooth. Carry that test to pin the mechanism,
`the_peak_moves_with_the_generated_constants` to pin that it is an output, and
report the edge cases rather than asserting them away.

*Mass exactness: one of the two constants is load-bearing, not both.* `Mass` is
fixed-point at SCALE = 1024. `units × base_mass` is never rounded, so
**`base_mass` must be dyadic** — probed, drawing it in steps of 0.3 instead of
0.25 fails exactness at `N = 1`. The defect is quantised explicitly, so
**`contact_defect` need not be** — probed, changing its denominator from 512 to
500 leaves the test passing, while deleting the quantisation fails it at
`N = 2`. An earlier comment called both load-bearing; a future reader acting on
that would protect the wrong half.

*Quantise with `round_ties_even`, matching `Mass::from_f64_quantised`.* Two
rounding conventions for one grid is not hypothetical here: `f64::round` is
ties-away and `from_f64_quantised` is ties-even, and the ties are **reachable** —
13 in the mass series and 2 in the valence series, landing on N = 2, 3, 4 and 7,
the lightest and most abundant elements. Both conventions are IEEE-754-exact, so
this is not a portability bug; it is that a later "harmonise the rounding"
cleanup moves a golden and reads as tidying.

**3. Abundance is the gel lever, and Task 4 must not claim the beaker is safe.**

§7.2: a giant component appears at bond-conversion extent `p_c = 1/(f_w − 1)`
with `f_w = ⟨f²⟩/⟨f⟩`, and a gelled beaker passes the polymer floor. A valence
*ceiling* of 8 is fine; a distribution *centred* near 8 is not.

Abundance is derived, and it has exactly one term: fusion builds heavy clusters
from light ones, so each extra unit costs a step and abundance falls
geometrically. Sequential addition with a constant per-step survival gives
`r^N = exp(N·ln r)`.

```
abundance(N) ∝ exp(−decay·N)
```

**An energy tilt was removed, and that is a finding rather than a
simplification.** A draft multiplied this by `exp(0.6·E_per_unit)`, described as
"tilted by how well the cluster binds". Three things were wrong with it:

- *It pushed the wrong way* — this bullet is the weakest of the three, and its
  numbers are the least trustworthy in this section. Deleting the tilt was
  measured to move median `p_c` 0.552 → 0.646 (+17%) against bonds-per-node
  **0.6269 → 0.6247 (−0.35%)** — i.e. it barely moves in the invariant
  coordinate, which is the point that survives. **Both figures predate the
  `FRONTIER_COEFF` refit** (0.646 sits at the pre-refit median 0.649, not at
  HEAD's 0.741) **and cannot be re-derived, because the tilt was removed from
  the probe along with the claim.** Treat the −0.35% as directional, not as a
  measurement. Lead with the other two reasons, which stand on their own and do
  not depend on a number nothing can reproduce.
- *The stated mechanism derives `E_total`, not `E_per_unit`.* Compounding a
  per-step survival gives `exp(β·E_total − d·N)`. Implementing the stated story
  makes the **heaviest** element the most abundant and collapses `p_c` to 0.112;
  making it behave needs β 30–120× smaller. The N-dependence was chosen for the
  answer it produced.
- *`0.6` was typed in while every neighbour is drawn.* That is structurally the
  same defect as `peak`-as-an-argument, which is what this scheme exists to
  remove — milder, because it only shifts a reported result rather than being
  reported back as its own output, but the same shape.

**Measured, with the corrected geometry.** Nominal `p_c` spans **0.47 to 0.91**
across 24 universes, median 0.74. An earlier version reported 0.22–0.41 and
concluded abundance was insufficient; those figures carried the 1.46× frontier
error, which inflated every valence and therefore every `f_w`.

**But most of that is coordinate, not safety, and the probe now says so.**
Abundance weighting moves the extent by **+85%** and bonds-per-node at gel by
**+9%** — so roughly 89% of what "abundance is the gel lever" appears to measure
is mean-degree rescaling. The lever is real, because the reweighting genuinely
is degree-correlated, but it is ~9.4× smaller than the extent figure suggests
(85.1/9.1). An earlier version of this sentence said ~6×, which contradicted the
89% in the line above it — `1 − 9.1/85.1 = 89.3%` implies 9.4×, and the two
numbers in one argument cannot both be right. Report both.

**Task 4 gates on nothing, and the reason has now been wrong twice.** The first
version argued burial makes realised functionality lower, so realised `p_c` is
higher, so the figures are conservative. The correction pointed out that
`p_c' = p_c/q` exactly, so only the coordinate moved. **Both are incomplete:
they compare thresholds without an operating point**, and reporting a second
threshold changes nothing, because the ratio of where-the-beaker-sits to
where-it-gels is identical in either coordinate.

Put the operating point in — §9.1's bimolecular Condense against §9.4's
unimolecular Cleave, steady state `(1−p)²/p = k_r/(2·k_f·n·⟨f⟩)` — and burial
moves the beaker *away* from gel, monotonically. The margin between `q` = 1.0
and `q` = 0.5 is `F(R) = 2·p_ss(R)/p_ss(2R)`, in which `p_c` and `f_w` cancel,
so it depends only on the rate ratio and is **bounded in (2, 4)**: → 2 at
near-full conversion, → 4 when dilute. An earlier version of this paragraph said
"~2.3×, robust across three orders of magnitude"; it is neither, and `F = 2.3`
implies an operating point at 96.7% of the gel threshold — a hidden assumption,
in the paragraph whose whole point is that the earlier versions hid one. So the
original intuition was defensible after all, for a reason neither earlier
version gave. §7.2 carries the derivation and the two limits.

Task 4 has no rate constants and therefore no operating point, which is exactly
why it gates on nothing — not because its numbers are conservative. It reports
`f_w` and bonds-per-node as diagnostics. **The gate is Task 20's battery**, on
`p_ss / p_c`. (A draft deferred to "Task 5's battery"; Task 5 creates `bonds.rs`
and has no battery and architecturally cannot have one. §7.2's ceiling had named
no task since PR #8 added it; it is now Task 20's, with the criteria written
there.)

*One reading worth carrying forward:* the binding peak sits at a closure, and a
closure has valence 0. So the most tightly-bound, longest-lived element is the
one that cannot bond. That is self-consistent and G3-safe, but it interacts
directly with the decay band and belongs in Task 5's inheritance.

#### Carried to Task 5

Task 5 derives `bond_energies` and must make it a function of the same per-unit
binding energy this task derives, not an independently drawn matrix. Two
encodings of "these elements bind well" in incommensurable units is exactly the
defect that made `peak` unfalsifiable here, one level up. `Element` therefore
exposes `energy_per_unit` for Task 5 to consume, and Task 5's tests must show
bond energy moving when it moves.

```rust
/// Mint one element name, unique against `taken` and clear of the blocklist.
///
/// `taken` accumulates symbols already used in this universe and is mutated.
///
/// **The symbol space is 165, not the 702 an earlier version of this comment
/// implied by "26x27".** Enumerated exhaustively over the grammar: 7 one-letter
/// and 158 two-letter symbols survive the blocklist, because only the 14
/// distinct initials of `ONSETS` can start one and the second letter must
/// appear in the same generated name. Against a table that reaches 120 that is
/// 1.4x headroom. Filling 120 elements takes **480 attempts at the median**
/// (min 333, max 704, zero fallbacks over 2000 universes); the 120th element
/// alone needs a **mean of 11.5** attempts, p90 26, p95 33, p99 52, max 93.
///
/// An earlier version said "~38 retries" without saying which statistic that
/// was: it sits between p95 and p99, reached in 3.5% of universes, and reading
/// it as typical understates the headroom this paragraph is arguing for.
///
/// **The budget is a cliff, not a gradient, and it is worth naming.** Below the
/// symbol space a mint costs ~5.4 us at position 119; at 165 every mint burns
/// all 10 000 attempts at **6.07 ms**, a 1100x step. `n_elements` is drawn
/// 60..=120 so this is unreachable, and
/// `the_generator_covers_the_largest_table_without_falling_back` pins the
/// margin — but raising the draw to 200 without widening `ONSETS` turns a
/// 177 us universe into ~0.5 s, and no test would fail.
/// Which path produced a symbol.
///
/// The `Fallback` arm is a last resort and is **not well-formed past `Q9`** —
/// three characters, and a name carrying a digit. It exists so a test meaning
/// to exercise the generator can *say so*, rather than sniffing for a `Q`
/// prefix that only works because `ONSETS` happens to contain no `q`.
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Provenance {
    /// From the phonotactic grammar.
    Generated,
    /// From the exhaustion fallback.
    Fallback,
}

pub fn mint(rng: &mut Stream, taken: &mut Vec<String>) -> (String, String, Provenance) {
    for _ in 0..10_000 {
        let name =
            format!("{}{}{}{}", pick(rng, ONSETS), pick(rng, NUCLEI), pick(rng, CODAS), pick(rng, SUFFIXES));

        // Symbol: first letter, plus one later letter from the name itself so
        // the symbol visibly belongs to the word.
        let letters: Vec<char> = name.chars().collect();
        let mut symbol = String::new();
        symbol.push(letters[0].to_ascii_uppercase());
        if letters.len() > 2 && rng.next_f64() < 0.85 {
            let idx = 1 + rng.next_range((letters.len() - 1) as u64) as usize;
            symbol.push(letters[idx]);
        }

        if !is_real(&symbol, &name) && !taken.contains(&symbol) {
            taken.push(symbol.clone());
            return (symbol, name, Provenance::Generated);
        }
    }
    // Reachable at 166 mints, demonstrated — not "unreachable in practice" as
    // an earlier comment said. The fallback must therefore preserve the
    // uniqueness postcondition this function's own doc promises: a draft used
    // `taken.len() % 10`, giving ten symbols and an unconditional push, which
    // made the fallback the *only* path that could emit a duplicate. It did.
    //
    // Dropping the `% 10` makes it unique for as long as `taken` grows, which
    // is the postcondition. It does **not** make it well-formed: past `Q9` the
    // symbol is three characters and the name carries a digit, so both
    // `symbols_are_well_formed` and the 1..=2 length contract fail there.
    //
    // That is stated rather than fixed, deliberately. The real guarantee is the
    // margin — `the_symbol_space_exceeds_the_largest_table` — and a fallback
    // elaborate enough to stay well-formed would look like a guarantee while
    // still being a last resort. If a universe ever needs more than 165
    // elements, widen `ONSETS` and re-measure the space; do not extend this.
    // Bind the index once: a draft read `taken.len()` before the push for the
    // symbol and after it for the name, so they disagreed by one in the path
    // whose whole justification is "unique and traceable".
    let idx = taken.len();
    let symbol = format!("Q{idx}");
    taken.push(symbol.clone());
    (symbol, format!("quorium{idx}"), Provenance::Fallback)
}
```

```rust
//! How `N` base units pack into shells, and what that packing costs in
//! contacts (spec §7.1).
//!
//! Every element property in `element.rs` is a function of what this module
//! computes, which is the point: an element is not a row of drawn numbers, it
//! is a cluster of `N` units and its properties are consequences of the
//! cluster's shape.

/// Units in the `n`th shell: `k*n^2 + 2`. Only `k` is drawn.
///
/// **The `+ 2` is the Euler characteristic, not "the antipodal pair".** For any
/// convex simplicial polyhedron shell `n` holds `V + E(n-1) + F(n-1)(n-2)/2`;
/// apply `3F = 2E` and the linear term vanishes, and `V - E + F = 2` leaves
/// `(F/2)n^2 + 2`. So `k = F/2 = E/3 = V - 2`, and **`shell(1) = k + 2 = V`**,
/// which is what forces `z = k + 2` in [`PackingConsts`].
///
/// The tetrahedron falsifies the antipodal reading outright: `k = 2`,
/// shell 1 = 4 = 2*1^2 + 2, and it has no antipodal vertex pair at all. The
/// distinction changes no number here; it changes what the next person writes
/// when they generalise to a hemisphere or a torus.
///
/// `k` is how densely the base unit's own shape lets neighbours tile that
/// surface, and it is what makes two universes differ in table *shape*.
///
/// **Defined for `n >= 1`.** `shell_size(k, 0)` returns 2, which is
/// meaningless: shell 0 is the single central unit, and every caller
/// special-cases it.
///
/// `k = 10` recovers `10n^2 + 2` = 12, 42, 92, the shell populations of the
/// Mackay icosahedral packing (A. L. Mackay, 1962). **The magic numbers seen
/// experimentally are the *cumulative* sizes 13, 55, 147 — not these.** An
/// earlier version attached the real-world observation to the shell
/// populations, silently swapping the two quantities the rest of this comment
/// correctly distinguishes.
///
/// **This is not corroboration and must never be read as any.** `10n^2 + 2` is
/// the vertex count of the nth icosahedral geodesic subdivision, forced by
/// Euler's formula with twelve five-fold vertices — the same formula that
/// generates this project's own sampling family `D` in {12, 42, 162}. The shell
/// law is re-deriving a consequence of `chi = 2` the codebase needed anyway,
/// not reaching toward anything real. Nothing may ever bias the draw toward
/// `k = 10` on account of the coincidence, and no claim here depends on the
/// experiment: delete the sentence naming it and everything above still holds
/// (G3; see the task preamble for the full position).
///
/// **Do not reuse `Geodesic::dirs` as site positions.** The shared object is
/// the icosahedron's face tiling and rotation group, not the point set:
/// geodesic is `10*4^L + 2` = 12, 42, 162, 642 against packing's `k*n^2 + 2`.
/// At `k = 10` they coincide only where `n = 2^L`, so 92 has no geodesic rung
/// at all and 162 is a different point set (mismatch 2.29e-2, 8% of the
/// neighbour spacing). Right at 12 and 42, silently wrong at 162.
#[must_use]
pub const fn shell_size(k: usize, n: usize) -> usize {
    k * n * n + 2
}

/// Lateral coordination inside a shell — Euler's formula, not a tunable.
///
/// A triangulated sphere on `v` vertices has exactly `3v - 6` edges, so its
/// mean degree is `6 - 12/v`. The twelve five-coordinate sites Euler forces are
/// the same twelve wherever they sit.
#[must_use]
pub fn lateral_coordination(cap: usize) -> f64 {
    6.0 - 12.0 / cap as f64
}

/// Unmade lateral contacts on the frontier of a partly-filled shell.
///
/// The canonical filling order is a compact spherical cap growing from one
/// pole, so the frontier is a circle of latitude. A cap covering fraction `f`
/// subtends `cos(theta) = 1 - 2f`, so its boundary circle has radius
/// `2*sqrt(f(1-f))`; site spacing on a shell of `cap` sites is
/// `sqrt(4*pi/cap)`; so the boundary carries `2*sqrt(pi*cap*f(1-f))` sites,
/// each pointing **two** of its six contacts outward — not three, which is one
/// of the three errors the fitted [`FRONTIER_COEFF`] exists to absorb. The
/// coefficient is fitted to exact counts on real geodesic spheres, not derived
/// from this sketch; see its own doc comment before changing either.
///
/// **The discrete bound is not tidying, and it binds in exactly one place.**
/// At `outer = 1` the continuum form returns 6.46 (cap 8) to 6.87 (cap 128) for
/// a site whose shell offers 4.5 to 5.9. (An earlier version said "10.5
/// contacts for a site that has six" — both numbers were measured at the naive
/// 10.635 coefficient and are stale by two refits.) By symmetry the same holds
/// for the `cap - a` empty sites, so the smaller side binds.
///
/// Measured, the discrete branch is taken iff `compact_bound(a) < COEFF*sqrt(a)`,
/// which at 6.90 is true only at `a = 1`: 54 of the 1287 `(cap, outer)` cells
/// the table reaches, all at `min(outer, cap-outer) == 1`.
///
/// **It does not by itself stop `lateral_made` going negative** — an earlier
/// version of this comment implied it did. `compact_bound(1) = 6` exceeds
/// `lateral_coordination(cap)` for every cap in the table, so the raw value is
/// negative at every `outer == 1` cell and it is `lateral_made`'s own clamp
/// that returns 0. See that function.
///
/// **There is deliberately no `if outer == 0 { return 0.0 }` here.** It would
/// be redundant — both factors already vanish at a closure — and a redundant
/// special case on a chemically-loaded predicate is how a detector quietly
/// becomes a declaration two refactors later.
///
/// The property that no branch reads the closure predicate is checked at
/// *source* level by `xtask` (Step 8c), not behaviourally: deletion is
/// uninformative here because two independent factors hold the zero, and
/// continuity was shown defeatable. `element.rs`'s continuity assertion is a
/// backstop, not the guarantee.
#[must_use]
pub fn unmade_lateral(cap: usize, outer: usize) -> f64 {
    let f = outer as f64 / cap as f64;
    // `sqrt` stays native: IEEE-754 specifies it exactly, so it is portable
    // without `det_math`. See the criterion in `clippy.toml`.
    let continuum = FRONTIER_COEFF * (cap as f64 * f * (1.0 - f)).sqrt();
    let smaller = if outer < cap - outer { outer } else { cap - outer };
    if continuum < compact_bound(smaller) { continuum } else { compact_bound(smaller) }
}

/// Frontier-length coefficient, **fitted to exact counts on real triangulated
/// spheres** rather than derived.
///
/// **Cap-dependent, so a single constant is a compromise.** Least-squares
/// against exact counts gives 6.075 at D = 12, 7.078 at D = 42 and 7.316 at
/// D = 162 — finite-size effects pull it down at small caps, where Euler's
/// twelve pentagons are a large fraction of the shell. This table's caps run
/// 8..128, and D = 12 and D = 42 are real shells (`shell_size(10,1)`,
/// `shell_size(10,2)`); D = 162 is not one of them. 6.90 minimises worst-case
/// error across all three.
///
/// The naive derivation gives `6*sqrt(pi) = 10.635` and is wrong by 1.46x, for
/// **three** reasons, not the two an earlier version listed: a boundary site
/// points *two* of six contacts outward, not three; the spacing must carry the
/// triangular lattice's `(sqrt(3)/2)s^2` area-per-site; and a lattice boundary
/// zig-zags through ~10% more sites than `L/s`. The first two alone give 6.598,
/// so a reader re-deriving from them would "fix" the constant downward. The
/// derivation that reproduces the measurement is Cauchy's line-crossing
/// formula: `16*sqrt(3)*sqrt(sqrt(3)/(8*pi))` = 7.2751, asymptotic.
///
/// `frontier_matches_exact_counts_on_a_real_sphere` holds this to the geometry
/// at **all three levels** at 0.25, admitting [6.2, 7.2]. An earlier version
/// gated D = 162 alone and admitted -22%/+29% — a band over which the valence
/// series moves in up to 23 of 24 universes.
pub const FRONTIER_COEFF: f64 = 6.90;

/// **Minimum** unmade lateral contacts a patch of `a` sites can expose.
///
/// Harborth's result gives the **maximum** internal bonds over all arrangements
/// of `a` cells, `floor(3a - sqrt(12a - 3))`, attained by the compact ones — an
/// upper bound on internal bonds and therefore a **lower** bound on exposure,
/// with equality only for maximally compact patches. "At least ... so it
/// exposes at most" inverts it; a cap-order fill is not maximally compact, and
/// on a `Geodesic<162>` `a = 3` exposes 14 against this bound's 12. Verified by
/// brute force over every connected animal for `a = 1..10`.
///
/// A bare `6a` is the *dispersed* bound and contradicts the compactness the
/// continuum assumes. Its recorded symptom — "valence 3 where the exact count
/// gives 2 at `a = 3`" — was measured at the naive 10.635 coefficient and is
/// unreachable at 6.90.
///
/// The result is provably positive (`>= 2*sqrt(12a-3)`, since `floor(x) <= x`;
/// brute-forced to a = 20000, minimum 6.0 at a = 1), so **no clamp is
/// written** — a guard with no reachable case reads as evidence the case
/// exists. An earlier version of this block wrote one anyway, four lines under
/// this sentence.
#[must_use]
pub fn compact_bound(a: usize) -> f64 {
    if a == 0 {
        return 0.0;
    }
    let af = a as f64;
    let internal = (3.0 * af - (12.0 * af - 3.0).sqrt()).floor();
    6.0 * af - 2.0 * internal
}

/// Lateral contacts *made* inside a partly-filled shell.
///
/// Identity, not a model: summing lateral degree over the filled sites counts
/// every internal contact twice and every frontier contact once. At a full
/// shell the frontier is empty and this returns `3*cap - 6` exactly, which is
/// the check that the two halves agree.
///
/// **The identity holds everywhere except `outer == 1`, where the clamp below
/// is load-bearing — name it, do not delete it.** The two halves use different
/// coordination conventions: `compact_bound(1) = 6` is a flat-lattice degree,
/// `lateral_coordination(cap) = 6 - 12/cap` is the sphere's, and the second is
/// strictly smaller for every cap. So the raw value is negative at every
/// `outer == 1` cell (36 of 2808 over k = 6..14, shells 1..4; worst −0.75 at
/// cap = 8) and the clamp is what returns the correct 0.
///
/// `a_two_unit_cluster_has_exactly_one_contact` — the test that caught the
/// `z = 6 + k/2` defect — passes *only* because of it: unclamped,
/// `contacts_upto(c, 2)` is 0.250 / 0.500 / 0.625 at k = 6 / 10 / 14 against a
/// 1e-9 tolerance. `the_clamp_fires_only_at_a_lone_outer_site` pins that, so a
/// later "simplify the clamp away" fails a test instead of silently adding
/// spurious made contacts while every valence still reads plausibly.
#[must_use]
pub fn lateral_made(cap: usize, outer: usize) -> f64 {
    let raw = lateral_made_raw(cap, outer);
    if raw > 0.0 { raw } else { 0.0 }
}

/// `lateral_made` before the clamp, so a test can assert *where* the clamp
/// fires rather than leaving it an unnamed rescue inside a function whose doc
/// calls itself an identity.
#[must_use]
pub fn lateral_made_raw(cap: usize, outer: usize) -> f64 {
    (lateral_coordination(cap) * outer as f64 - unmade_lateral(cap, outer)) * 0.5
}

/// The packing constants of one universe.
#[derive(Debug, Clone, Copy, PartialEq)]
pub struct PackingConsts {
    k: usize,
    z: f64,
}

impl PackingConsts {
    /// The only constructor, and the fields are private, because `z` is not an
    /// independent parameter: `shell_size(k, 1) == k + 2` is the set of units
    /// touching the core, which is what `z` means. Written out by hand at three
    /// sites in an earlier draft, correct at all three by luck of copy-paste,
    /// with a doc comment saying "follows `k`, and must" above two `pub` fields
    /// that let `PackingConsts { k: 6, z: 40.0 }` compile.
    ///
    /// `z` feeds `contacts_upto`, which sets the binding peak, which sets
    /// `decay_rate` and `abundance`. A fourth call site transposing the
    /// constant produces a plausible table.
    #[must_use]
    pub fn new(k: usize) -> Self {
        Self { k, z: shell_size(k, 1) as f64 }
    }

    /// Sites per unit area of shell — the drawn part of the shell law.
    #[must_use]
    pub const fn k(self) -> usize {
        self.k
    }

    #[must_use]
    pub const fn z(self) -> f64 {

    }

/// Contacts made by a cluster of `units`, accumulated shell by shell.
///
/// **A continuum count does not work and looks fine while failing.** The
/// obvious form — `z*n/2` less a surface deficit growing as `n^(2/3)` — has
/// the deficit exceeding `n` itself for everything below `n = 113`, so it
/// collapses to `z*n/4`, makes contacts-per-unit a *constant*, and removes the
/// binding peak entirely. Measured: the peak sat at `N = 1` in all 24 drawn
/// universes, reported as "lands on a closure in 24 of 24" because 1 is the
/// first closure.
///
/// So: each shell's sites make inward contacts to the shell below and lateral
/// contacts to their own neighbours, and the inward budget is whatever outward
/// capacity the shell below has left after its own inward and lateral contacts
/// are accounted for. That recursion is what makes contacts-per-unit *rise*
/// toward `z/2`, which is what a binding peak needs.
///
/// Accumulation is in shell order and must stay that way (§13.4).
#[must_use]
pub fn contacts_upto(c: PackingConsts, units: usize) -> f64 {
    if units <= 1 {
        return 0.0;
    }
    let mut total = 0.0_f64;
    let mut remaining = units - 1;
    // The core: one site, no lateral neighbours, no inward contacts, so its
    // whole coordination points outward.
    let (mut prev_cap, mut prev_z_lat, mut prev_inward) = (1_usize, 0.0_f64, 0.0_f64);
    let mut shell = 1_usize;
    while remaining > 0 {
        let cap = shell_size(c.k, shell);
        let take = if remaining < cap { remaining } else { cap };
        let outward_budget = prev_cap as f64 * (c.z - prev_z_lat - prev_inward);
        let inward_per_site = outward_budget / cap as f64;

        total += inward_per_site * take as f64;
        total += lateral_made(cap, take);

        remaining -= take;
        prev_cap = cap;
        prev_z_lat = lateral_coordination(cap);
        prev_inward = inward_per_site;
        shell += 1;
    }
    total
}

/// Cumulative shell closures inside a table of `n` elements.
///
/// `1` is always the first: a single unit is a closed cluster with no frontier.
#[must_use]
pub fn closures(k: usize, n: usize) -> Vec<usize> {
    let mut out = vec![1_usize];
    let (mut total, mut shell) = (1_usize, 0_usize);
    loop {
        shell += 1;
        total += shell_size(k, shell);
        if total > n {
            return out;
        }
        out.push(total);
    }
}
```

```rust
#[derive(Debug, Clone, PartialEq)]
pub struct Element {
    pub id: ElementId,
    pub symbol: String,
    pub name: String,
    /// Base units in this element's cluster. The element *is* this number.
    pub units: usize,
    /// Which shell is filling. The period index, derived rather than drawn.
    pub period: u8,
    /// Units in the incomplete outer shell. The group index.
    pub group: u8,
    pub mass: Mass,
    /// Bonding slots: unmade lateral contacts on the frontier, over the
    /// lateral coordination. Zero at a closure because a closed shell has no
    /// frontier — not because a branch says so.
    pub valence: u8,
    /// Exposed fraction of the cluster, mapped to [-1, +1]. Drives
    /// complementarity in §8.3. **Not** electronegativity: different range,
    /// different meaning, different behaviour (G3).
    pub affinity: f64,
    pub radius: Span,
    /// Binding energy per unit: made contacts, less radial strain.
    ///
    /// **Task 5 must derive `bond_energies` from this**, not draw an
    /// independent matrix. Two encodings of "these elements bind well" in
    /// incommensurable units is the defect that made the predecessor's `peak`
    /// unfalsifiable, one level up.
    ///
    /// **G4 note, flagged deliberately rather than silently accepted.** This is
    /// an energy travelling as a bare `f64` into a task that mints it as
    /// [`Quanta`] at the far end, with no type-level relationship — the exact
    /// "bare `f64` carrying a quantity through three functions defeats this
    /// quietly" shape §5's G4 exists to stop. `borbax-units` provides
    /// `Div<f64> for Quanta`, so cluster-energy-per-unit is expressible as
    /// `Quanta` and this *could* be typed. It is left bare for now because
    /// `energy_per_unit` is also compared, summed and scaled inside this file
    /// where the newtype buys nothing, and changing it is Task 5's call when it
    /// writes the consumer. **Task 5 must decide explicitly**, not inherit the
    /// `f64` by default — that decision is what sets the precedent for every
    /// energy that follows.
    pub energy_per_unit: f64,
    /// Decay probability per world-year, from the distance below the binding
    /// peak. **Named for what it holds** — it is 0 at the peak and rises toward
    /// the extremes. An earlier draft called this `stability`, which inverted
    /// the sense of the field against its own description, in the quantity
    /// §9.4 calls the most sensitive parameter in the system. Unstable elements are both an energy source and a mutation
    /// source (spec §9.5).
    pub decay_rate: f64,
    /// Relative abundance. **The gel lever** (§7.2) — see `generate_elements`.
    pub abundance: f64,
    /// Which band of outer-shell occupancy this element exposes — `floor(fill ×
    /// n_bands)`.
    ///
    /// **Not derived, and this doc is what `cargo doc` renders.** An earlier
    /// version said "coordination class of the frontier sites"; no coordination
    /// mix is computed anywhere, and enumerated across all `k`, `n_bands`
    /// and `N` this takes exactly one value per `(outer, cap)` pair — zero
    /// information beyond `group`. Nothing downstream may branch on it as
    /// though it carried chemistry.
    pub outer_fill_band: u8,
}

/// The derived shape of one universe's table.
#[derive(Debug, Clone, PartialEq)]
pub struct ShellPattern {
    /// The drawn part of the shell law: shell `n` holds `k*n^2 + 2` units.
    pub k: usize,
    /// Cumulative unit counts at which a shell closes. Derived from `k`, not
    /// drawn — this replaces the predecessor's drawn table of period lengths.
    pub closures: Vec<usize>,
    /// Where the per-unit binding energy peaks. **Read off the finished
    /// series, never passed in** — that is the property distinguishing this
    /// from the predecessor, in which `peak` was an argument whose value was
    /// then reported back as an emergent minimum.
    pub peak: usize,
}

/// Convenience for tests and callers that need the universe-domain stream.
#[must_use]
pub fn stream(seed: u64) -> Stream {
    Stream::new(seed, Domain::Universe, 0)
}

/// Build a universe's periodic table by fusion.
///
/// **There is no `peak` parameter and there must never be one.** The
/// predecessor took one, computed instability as `((N - peak)/peak)^2`, and
/// reported the resulting minimum as emergent — it was the distance from a
/// typed-in constant, and sweeping `peak` landed the minimum on a closure in
/// 13 of 24 draws. Here one binding energy per unit is derived from the
/// packing counts and both the mass defect and the decay rate are functions
/// of it.
///
/// Infallible: the mass is built in sub-units and handed to `Mass::from_raw`,
/// so there is no range check to fail and no error to propagate. See the task
/// preamble for why a draft made it fallible and why that was wrong.
pub fn generate_elements(seed: u64) -> (ShellPattern, Vec<Element>) {
    let mut rng = stream(seed);

    // `k` spans 6..=14. Below 6 a shell cannot triangulate a sphere; above 14
    // the second shell exceeds 200 units, so a 120-element table never leaves
    // it and there are no families at all.
    let k = 6 + rng.next_range(9) as usize;
    // `z = k + 2` is forced by the shell law, not chosen: `shell(1) = k + 2` and
    // shell 1 *is* the units touching the core. An earlier `6 + k/2` agreed only
    // at k = 8 and put 16 sites in shell 1 around a core with 13 neighbours.
    // Construct through `PackingConsts::new` so the relation has one home.
    let pack = PackingConsts::new(k);

    // **`base_mass` must be dyadic and `contact_defect` need not be.** `Mass`
    // is fixed-point at SCALE = 1024; `units * base_mass` is never rounded, so
    // that factor has to land on the grid by itself, while the defect is
    // quantised explicitly below. Probed both ways: drawing `base_mass` in
    // steps of 0.3 fails exactness at N = 1, changing `contact_defect`'s
    // denominator from 512 to 500 changes nothing, and deleting the
    // quantisation fails at N = 2. An earlier comment called both
    // load-bearing, which would have sent a future reader to guard the wrong
    // half.
    let base_mass = 1.0 + 0.25 * rng.next_range(4) as f64;
    let contact_defect = (1 + rng.next_range(4)) as f64 / 512.0;
    let base_radius = 0.30 + 0.02 * rng.next_range(11) as f64;
    let eps = 0.8 + 0.05 * rng.next_range(9) as f64;
    let sigma = 0.02 + 0.01 * rng.next_range(12) as f64;
    let decay = 0.04 + 0.01 * rng.next_range(13) as f64;
    let n_elements = 60 + rng.next_range(61) as usize; // 60..=120
    let n_bands = 3 + rng.next_range(4) as u8;

    let mut naming_rng = Stream::new(seed, Domain::Naming, 0);
    let mut taken = Vec::new();
    let mut out: Vec<Element> = Vec::with_capacity(n_elements);

    for units in 1..=n_elements {
        // Which shell is filling, and how far into it.
        let (mut shell, mut filled) = (0_usize, 1_usize);
        while filled + packing::shell_size(k, shell + 1) <= units {
            shell += 1;
            filled += packing::shell_size(k, shell);
        }
        let outer = units - filled;
        let cap = packing::shell_size(k, shell + 1);
        let contacts = packing::contacts_upto(pack, units);

        let (symbol, name, _) = naming::mint(&mut naming_rng, &mut taken);

        // Mass, in sub-units of 1/1024, so the grid is a property of the
        // construction rather than a claim about it. `base_mass` is drawn on a
        // 0.25 step so `base_mass * 1024.0` is an exact integer; the defect is
        // quantised with `round_ties_even` to match `Mass`'s own convention —
        // ties are reachable (13 in this series, at N = 2, 3, 4, 7 among
        // others), and two conventions for one grid means a later "harmonise
        // the rounding" cleanup silently moves a golden.
        let base_sub = (base_mass * 1024.0).round_ties_even() as i64;
        let defect_sub = (contacts * contact_defect * 1024.0).round_ties_even() as i64;
        let mass = Mass::from_raw(units as i64 * base_sub - defect_sub);

        // Radius: the cube root of the unit count, times a bulge for the
        // partly-filled outer shell sitting proud of the packed core.
        //
        // G3: real atomic radius *decreases* across a period and jumps at a
        // new one. This does the opposite — grows through a shell, drops at
        // closure. Structurally anti-isomorphic, not a renamed trend.
        // **Radius is set by which shell is occupied, and it cannot shrink.** The
        // enclosing radius of a superset of units is never smaller, and an
        // earlier `cbrt(units) * (1 + 0.55*fill)` collapsed it 35% at every
        // closure (N=74 -> 75: 2.587 -> 1.687 on one unit added). Since G1
        // measured binding at ~93% size and ~7% shape, that cliff would have
        // read as closed-shell elements binding a different partner set — an
        // arithmetic accident wearing the look of interesting periodicity.
        //
        // For a shelled cluster the radius *is* the shell index: each shell adds
        // one lattice spacing. So `shell + fill` is both monotone and the better
        // model, and it recovers `N^(1/3)` asymptotically since N ~ k*shell^3/3.
        // Over the range a table actually spans the fitted exponent is
        // 0.29..0.32 against a true cube root's 0.333 — the `1.0 +` offset drags
        // it down. Not a defect; an unqualified range claim would be.
        //
        // G3 still holds, by a cleaner route: real atomic radius falls across a
        // period and jumps at a new one. This rises monotonically and never
        // jumps — structurally unlike, without being geometrically wrong.
        let fill = outer as f64 / cap as f64;
        let radius = base_radius * (1.0 + shell as f64 + fill);

        // Valence: docking notches on the frontier. Zero at a closure because
        // there is no frontier there.
        // `round_ties_even`, for the same reason as the mass defect: `notches`
        // lands on an exact 2.5 at k=8/outer=2 and k=8/outer=8, where ties-away
        // and ties-even differ by a whole bonding slot.
        let notches = packing::unmade_lateral(cap, outer) / packing::lateral_coordination(cap);
        let valence = notches.round_ties_even() as u8;

        // Affinity: exposed fraction of the cluster. Continuous across every
        // closure by construction — at `outer == 0` it reduces to the
        // outermost complete shell, and at `outer == cap` to the same
        // expression for the next one.
        let shell_units = if shell == 0 { 1 } else { packing::shell_size(k, shell) };
        let inner = filled - shell_units;
        let covered = shell_units as f64 * outer as f64 / cap as f64;
        let surface = units as f64 - (inner as f64 + covered);
        let affinity = 2.0 * (surface / units as f64) - 1.0;

        // Per-unit binding energy: made contacts, less radial strain.
        //
        // **The strain term is the invented destabiliser, and the obvious one
        // is a G3 breach.** The familiar way to bend a binding curve back down
        // is the semi-empirical mass formula's Coulomb term, and reaching for
        // it imports real nuclear physics with no data file in sight. This is a
        // different mechanism: a lattice cannot tile a sphere, so each shell is
        // stretched over a larger radius than the one below and carries a
        // strain growing as `n^2`, which competes with the contact term's
        // saturation and produces a maximum.
        //
        // (The defence "no charge, no isospin, no pairing and no asymmetry
        // term" stood here and is deleted: it enumerates the terms that are
        // *absent* and says nothing about the one that is present, which is the
        // shape of the `libm` doctrine error. §7.2's prose forbids it.)
        //
        // **The exponent 2/3 is CHOSEN, not derived, and it is load-bearing.**
        // Per-*shell* strain proportional to `n^2`, summed and divided by `N`,
        // gives `1/k` — a constant, not `N^(2/3)`. Reaching 2/3 needs
        // per-*site* strain proportional to `n^2`, which is a different claim.
        // Accumulating shell-by-shell instead — as `contacts_upto` does, for
        // the identical reason — moves the peak in **48.1% of drawn
        // universes**, so the `19 of 24` closure census is a property of this
        // choice and not of the packing. Deferred to Task 20 deliberately:
        // precedence 2, not a G3 breach, remedy known and it requotes every
        // number. Do not describe the exponent as derived.
        let energy_per_unit =
            eps * contacts / units as f64 - sigma * det_math::cbrt((units * units) as f64);

        // Abundance: fusion builds heavy clusters from light ones, so each
        // extra unit costs a step and abundance falls geometrically. Sequential
        // addition with a constant per-step survival gives `r^N = exp(N ln r)`.
        //
        // **There is deliberately no `exp(beta * energy_per_unit)` tilt.** A
        // draft had one at beta = 0.6. It pushed the *wrong way* — deleting it
        // moves nominal p_c from 0.358 to 0.381, better than the best the whole
        // `decay` sweep reaches. Its stated mechanism compounds to `E_total`,
        // not `E_per_unit`; implementing the stated story makes the heaviest
        // element the most abundant and collapses p_c to 0.112. And 0.6 was
        // typed in where every neighbouring constant is drawn, which is the
        // same shape of defect as `peak`-as-an-argument.
        //
        // **This is the gel lever (§7.2) and Task 4 gates on nothing.** Measured
        // nominal p_c is 0.47..0.91 across 24 universes (median 0.74) — the
        // figure `gel_band_holds` asserts, which is where to re-read it rather
        // than trusting this comment. Do NOT justify that with
        // "burial makes realised functionality lower, so realised p_c is higher"
        // — §7.2 carried that argument and it is wrong: under degree-independent
        // thinning the beaker gels at the same bonds per atom regardless, and
        // only the coordinate was rescaled. Report nominal f_w and
        // bonds-per-node at gel as diagnostics; the gate is Task 20's
        // battery, on `p_ss / p_c`. (A draft said Task 5, which creates
        // `bonds.rs` and has no battery and cannot have one.)
        let abundance = det_math::exp(-(units as f64) * decay);

        // Catalytic class: which band of outer-shell occupancy this element
        // exposes.
        //
        // **This is a rebinning of `(period, group)`, and the claim is narrowed
        // to say so.** A draft's comment here said Euler's twelve five-coordinate sites
        // mean a sparsely-filled shell exposes a different coordination mix from
        // a nearly-full one, "and that mix is what a mineral surface presents".
        // The code computed no such mix. Enumerated across all k, n_bands
        // and N, this takes exactly one value per `(outer, cap)` pair — zero
        // information beyond `group`. Two reviewers found it independently.
        //
        // So Task 4's headline is five §7.1 properties derived, plus
        // `abundance` — and this one honest rebinning, named as such.
        // Deriving it properly is possible — the five- versus six-coordinate
        // site mix on the frontier *is* computable, and depends on the filling
        // order — and is left to whoever needs it to mean something. Until then
        // nothing downstream may branch on it as though it carried chemistry.
        //
        // `outer < cap` by loop construction and `cap >= 8`, so this lands in
        // `0..n_bands` with neither a `max(1)` nor a trailing modulo.
        let outer_fill_band = ((outer * usize::from(n_bands)) / cap) as u8;

        out.push(Element {
            id: ElementId(out.len() as u8),
            symbol,
            name,
            units,
            period: shell as u8,
            group: outer as u8, // `outer < cap` and the table caps at 120
            mass,
            valence,
            affinity,
            radius: Span(radius),
            energy_per_unit,
            decay_rate: 0.0, // filled below, once the peak is known
            abundance,
            outer_fill_band,
        });
    }

    // **The peak is read off here, after the series exists.** This ordering is
    // the mechanism: nothing above could have consulted it.
    //
    // Every closure is a *local* maximum by mechanism — a closed shell has no
    // frontier, so it makes every lateral contact available to it and maximises
    // contacts per unit, giving a sawtooth. That is structural: zero failures
    // across the full (k, eps, sigma) product.
    //
    // The **global** max is not. A series truncated mid-shell can peak at its
    // edge, and over the drawn table size it does in 4 of 24, with one further
    // universe peaking mid-shell. Measured: on a closure in 19 of 24, 13
    // distinct peaks. Both errors have been made here — an earlier version
    // called it a coincidence rate, and its correction called it structural
    // without qualification. Neither is right.
    let peak = out
        .iter()
        .fold((1_usize, f64::MIN), |(bn, be), e| {
            if e.energy_per_unit > be { (e.units, e.energy_per_unit) } else { (bn, be) }
        })
        .0;

    // Stability: distance below the peak, so the most tightly bound elements
    // persist and the extremes decay. One quantity, two consequences — which
    // is what the predecessor's two unlinked encodings could not give.
    let peak_energy = out.get(peak - 1).map_or(0.0, |e| e.energy_per_unit);
    for e in &mut out {
        // `f64::max` is disallowed — it returns either input on a tie and
        // measured `(+0.0).max(-0.0)` differs between aarch64 and x86-64.
        let scale = peak_energy.abs();
        let scale = if scale > f64::EPSILON { scale } else { f64::EPSILON };
        let deficit = (peak_energy - e.energy_per_unit) / scale;
        // **Cap at 1.0, and the 0.9 it replaces was never argued.** `decay_rate`
        // is a probability per world-year (§7.1), so 1.0 is the value the type
        // implies and needs no defence. 0.9 does need one, and had none —
        // measured over the 2916-universe grid it binds on 1.19% of elements
        // but on **at least one element in every universe**, and those elements
        // sit at median position N/n_elements = 0.011: it is the monomer, the
        // feedstock, the most abundant species. So a bare 0.9 systematically
        // slowed the decay of the one species whose persistence matters most,
        // by up to 26%, as a side effect of a guard nobody described. The raw
        // deficit does exceed 1 (max measured 1.218), so a cap is genuinely
        // needed — it is the value that was wrong, not the clamp.
        //
        // If a future measurement wants the monomer to persist longer, that is
        // a physics claim about feedstock and belongs in §9.4 with the
        // measurement attached, not in a magic number here.
        e.decay_rate = if deficit > 1.0 { 1.0 } else { deficit };
    }

    let shell = ShellPattern { k, closures: packing::closures(k, n_elements), peak };
    (shell, out)
}
```

### Task 5: Bond energies and the assembled Universe

**Files:**
- Create: `crates/borbax-universe/src/bonds.rs`
- Modify: `crates/borbax-universe/src/lib.rs`
- Test: both

**Interfaces:**
- Consumes: `Element`, `ElementId`, `borbax_units::Quanta`
- Produces: `BondEnergyMatrix::energy(a, b, order) -> Quanta`, `UniverseConsts`, `PhysicsVersion`, `Universe` (carrying `physics: PhysicsVersion`), `Universe::generate(seed) -> Universe`, `Universe::generate_under(seed, PhysicsVersion) -> Universe`, `Universe::element(ElementId) -> &Element`

**`generate_under` is why the seam works, and it is easy to leave out.** A
universe is *derived* from its seed rather than serialised, so "reloading" one
means re-running generation. With only `generate(seed)`, once `V2` exists there
is no argument that could say which laws to apply and it will stamp whatever
the binary implements — the exact failure `physics` was added to prevent,
stated in that field's own test comment and unaddressed by its own interface
until this line. `generate(seed)` stays as `generate_under(seed, CURRENT)`, and
the address parser feeds `@1` into the other.

**Three decisions Task 4's review routed here, each with a discriminator.**

1. **`energy_per_unit` is a bare `f64` crossing a crate boundary, and Task 5 must
   decide that explicitly rather than inherit it.** §5's G4 is precedence 1 —
   absolute, nothing to trade against — and this is exactly the "bare `f64`
   carrying a quantity through three functions defeats this quietly" shape it
   exists to stop. `borbax-units` already provides `Div<f64> for Quanta`, so the
   type exists. Task 4 left it bare because the value is compared, summed and
   scaled inside `element.rs` where the newtype buys nothing; that argument does
   not extend past the boundary, and this task *is* the boundary.

   *Discriminator:* no energy-dimensioned quantity may cross `borbax-universe`'s
   public API as a bare `f64` — adding it to a `Span` or a `Thermal` must fail to
   compile. Deciding to keep the `f64` is a legitimate outcome; **inheriting it
   without deciding is not**, and the way to tell the difference is whether this
   step's commit message says which was chosen and why.

2. **`energy(a: &Element, b: &Element, order)` discards what `ElementId` is
   for.** A caller in a reaction-rate path holds `ElementId`s and would have to
   index the table to produce `&Element` before every lookup — coupling the rate
   loop to the element table's lifetime and to a struct 48 bytes of which are
   `String`. `energy(ElementId, ElementId, u8)` needs neither, and `ElementId` is
   documented in Task 4 as the newtype index that keeps `Mol12`'s atom array one
   byte per slot.

   *Discriminator:* the bond-energy lookup must be expressible without the
   element table in scope. Adding an `ElementId` overload *alongside* the
   `&Element` one does not satisfy it — the `&Element` form remaining is what
   lets a hot path pick it up.

3. **`ElementId` is write-only until this task, and the shape it lands in is
   `elements[id.0 as usize]`** — a panic site at every call site, in a workspace
   where `indexing_slicing` is `warn` under `-D warnings`. Task 5's first act
   would otherwise be an `#[expect]` per call site, or a `get()` with nothing to
   return. One struct closes it: `PeriodicTable { pattern, elements }` with
   `get(ElementId) -> Option<&Element>` and `iter() -> (ElementId, &Element)`,
   which also names the pair `generate_elements` currently returns as a bare
   tuple and gives `ElementId`'s field a reason to go private.

   *Discriminator:* a downstream crate must not be able to turn an `ElementId`
   into a `usize` index without a fallible lookup. "The tuple got a name" does
   not satisfy it.

**Task 4's rewrite changed this task's inputs, and the steps below have not been
updated for it.** `Element` gained `units`, `energy_per_unit` and `abundance`;
`period`/`group` are now the shell index and outer-shell occupancy rather than
drawn coordinates; `ShellPattern` carries `k`, `closures` and `peak` instead of
a `periods: Vec<u8>`. Reconcile the code below against `element.rs` before
executing, rather than assuming the field names still line up.

**One thing already resolved, recorded so it is not re-opened.** A draft of Task
4 made `generate_elements` fallible, because `Mass::from_f64_quantised` returns
a `Result`, and deferred a ~46-call-site signature change here as an open
choice. `Mass::from_raw(i64)` exists — public, `const`, infallible — and the
fusion mass is an exact integer count of 1/1024ths by construction, verified
bit-for-bit over 240 000 masses with 5 014× headroom. Task 4 builds the mass in
sub-units, so there is no error to propagate and nothing here changes.

**Carried from Task 4: bond energy must be a function of `Element::energy_per_unit`,

```rust
//! Generated bond energies (spec §7.1).
//!
//! Energy is a function of the two elements' *groups*, not their identities.
//! That is deliberate: it means bond strength is another property families
//! share, so "elements in this column form fragile bonds" is a true and
//! discoverable statement rather than noise.

use crate::element::Element;
use borbax_rng::Stream;
use borbax_units::Quanta;

#[derive(Debug, Clone, PartialEq)]
pub struct BondEnergyMatrix {
    n_groups: usize,
    /// Row-major, `n_groups * n_groups`, symmetric by construction.
    e: Vec<f64>,
    /// Multipliers for bond order 1, 2, 3.
    order_scale: [f64; 3],
}

impl BondEnergyMatrix {
    #[must_use]
    pub fn generate(elements: &[Element], rng: &mut Stream) -> Self {
        let n_groups = elements.iter().map(|e| e.group as usize).max().unwrap_or(0) + 1;
        let mut e = vec![0.0; n_groups * n_groups];

        let base = rng.next_f64_range(30.0, 90.0);
        // Complementary affinities bond strongly; like affinities bond weakly.
        // This is what ties bonding to the same affinity scalar that drives
        // surface complementarity in §8.3, rather than inventing a second axis.
        let polarity_weight = rng.next_f64_range(0.4, 1.2);

        // Mean affinity per group, so energy depends on the group's character.
        let mut group_affinity = vec![0.0; n_groups];
        let mut group_count = vec![0u32; n_groups];
        for el in elements {
            group_affinity[el.group as usize] += el.affinity;
            group_count[el.group as usize] += 1;
        }
        for g in 0..n_groups {
            if group_count[g] > 0 {
                group_affinity[g] /= f64::from(group_count[g]);
            }
        }

        for a in 0..n_groups {
            for b in a..n_groups {
                let opposition = -(group_affinity[a] * group_affinity[b]); // in [-1, 1]
                let noise = rng.next_normal() * 0.08;
                let v = base * (1.0 + polarity_weight * opposition + noise);
                let v = v.max(base * 0.15); // never zero, never negative
                e[a * n_groups + b] = v;
                e[b * n_groups + a] = v;
            }
        }

        let order_scale = [1.0, rng.next_f64_range(1.6, 2.1), rng.next_f64_range(2.2, 3.0)];
        Self { n_groups, e, order_scale }
    }

    /// Bond dissociation energy for a bond of the given order.
    /// Orders outside 1..=3 clamp rather than panic — a malformed molecule
    /// should be inert, not a crash.
    #[must_use]
    pub fn energy(&self, a: &Element, b: &Element, order: u8) -> Quanta {
        let (ga, gb) = (a.group as usize, b.group as usize);
        if ga >= self.n_groups || gb >= self.n_groups {
            return Quanta::ZERO;
        }
        let scale = self.order_scale[(order.clamp(1, 3) - 1) as usize];
        Quanta(self.e[ga * self.n_groups + gb] * scale)
    }
}
```

**The firewall this establishes, which is worth stating once and obeying
forever.** Two kinds of change look similar in a diff and are completely
different in consequence:

| Change | Touches | Effect on existing worlds |
|---|---|---|
| `affinity()`, folding, decay, generation | **physics** | every species in every world changes — needs a `PhysicsVersion` bump |
| world generator, environment, niche machinery, scaffolding | scaffolding — compatible, still subject to §3.6 | no effect on existing **chemistry**; world generation is a separate, currently unversioned breakage |

**§3.6 applies identically on both sides of this line. Being above the
chemistry buys compatibility, not permission.** The table's third column says
what it measures — effect on existing worlds — and nothing more. A
world-generator change that made condensation favourable wherever a template is
present sits in row two, needs no version bump, breaks no world, and is exactly
what §3.6 forbids.

That distinction was got wrong here on the first attempt, in a way worth
recording. §11 names POET and Minimal Criterion Coevolution as the candidates
for V3's niche machinery, and an earlier version of this section pre-cleared
them as "environmental: they generate challenges, they do not alter what a
molecule is". True, and not the test. The test is whether the machinery is
*conditioned on the outcome it exists to make probable* — and for both of these
it is, definitionally:

> POET: *"filters out child environments that appear too challenging or too
> trivial **for the current level of capability of agents**."*
>
> MCC: any maze that is **solved at least once** may reproduce.

The environment population's admission rule reads agent performance. Strip that
minimal criterion and what remains is random environment mutation, which is
what §11 already assumes will not work — so the machinery cannot be adopted
without adopting the conditioning. Transposed to Borbax: generate a tidal-flat
variant, keep it if the current chemistry *almost* produces a replicator. That
is "condensation is favoured when a template is present" implemented one level
up, where it is harder to see. The dice are not loaded; they are re-rolled
until they read the number we wanted.

§11's own wording is *"should be evaluated then, not assumed away now"*, and
that stands. If POET is wanted later, its minimal criterion has to be replaced
by something outcome-blind — environments admitted on an intrinsic diversity or
novelty-of-*conditions* measure, never on what the chemistry achieved in them.
The §15.3 neutral shadow does not rescue it either: a shadow run under the same
filtered environment stream inherits the same conditioning.

Voltage-gated transport is the awkward counter-example, and it is worse than a
version bump. If folding depends on a bulk field then **fold stops being a pure
function of the species** — it becomes a function of (species, local field),
which in the molecular tier is per-location and effectively per-molecule. That
is the §8.6 regression CLAUDE.md warns "arrives disguised as a small feature",
here disguised as a physics extension and nearly waved through as "fine".

There is a clean mitigation and it must be a stated precondition of that
version rather than a discovery made when the fold cache starts missing:
quantise the field into a small fixed number of bands and key the species cache
on `(species, band)`. Still per-species × a constant, and the intern-time work
stays intern-time.

Record the physics-level statement, too, not the phenomenon name. "Voltage-gated
transport" names a real biological mechanism, and the name is what gets
implemented in two years — it invites `if species.is_pore { permeability *= f(v) }`,
a species-classification branch. *"An environmental scalar enters the fold
energy for every species"* cannot be written that way.

//! A generated universe: the laws of physics for one `universe_seed`.
//!
//! Generated once, then immutable. Everything downstream — worlds, molecules,
//! reactions — reads these constants and never changes them.

pub mod bonds;
pub mod element;
pub mod naming;

pub use bonds::BondEnergyMatrix;
pub use element::{Element, ElementId, ShellPattern};

use borbax_rng::{Domain, Stream};
use borbax_units::Thermal;

/// Universe-wide constants. Every one is generated, so two universes differ
/// in character rather than merely in their random draws.
#[derive(Debug, Clone, PartialEq)]
pub struct UniverseConsts {
    /// Target separation for a complementary fit in §8.3. Two surfaces
    /// interlock when their extents sum to about this.
    pub ideal_gap: f64,
    /// Relative weight of geometric fit vs surface-character opposition.
    pub w_shape: f64,
    pub w_charge: f64,
    /// Pre-exponential factor in the Arrhenius rate law (§9.1).
    pub rate_prefactor: f64,
    /// Global spontaneous-cleavage scale. V0 locates the decay band by
    /// moving this single number (spec §22.6); per-bond rates come later.
    pub decay_scale: f64,
    /// Which element acts as solvent. Its complementarity against a bond
    /// determines solvent attack (§9.5).
    pub solvent: ElementId,
    pub temp_min: Thermal,
    pub temp_max: Thermal,
}

/// The laws a universe was generated under.
///
/// **A universe is `(seed, physics)`, not `seed`.** §6 promises that
/// sharing `U-7F3A21C9` means the recipient gets the same planet; today the
/// real identity is `(seed, git SHA, rustc version)` and only the first third
/// is written down. This field writes down the rest of what matters.
///
/// The cost is stated honestly: every version here is a code path kept alive
/// forever, with its own goldens. That is the price of never breaking a world
/// somebody cared about, and it is bounded — versions are added when physics
/// changes, which should be roughly never.
///
/// **Gate on this, never on a zero weight.** The tempting shortcut for an
/// added term is to give it weight `0.0` for old universes and claim they are
/// unchanged. They are not: `0.0 * x` is `NaN` when `x` is infinite or NaN,
/// and a stray NaN's sign bit differs between the CI architectures (see
/// `det_math`). An inert term must be *skipped*:
///
/// ```text
/// if u.physics >= PhysicsVersion::V2 { score += w_field * field_term; }   // yes
/// score += u.consts.w_field * field_term;                                 // no
/// ```
///
/// New constants for a new version come from a **new `Domain`** (Task 3), so
/// adding them leaves every draw an existing universe already made untouched.
/// Those two rules together are what make a later law additive rather than
/// destructive.
///
/// # The admission criterion, which is not the same as the cost
///
/// This documents what a new version *costs* and offers no rule for when one
/// is *allowed*, and that gap is load-bearing. Before the seam existed, adding
/// a law carried a deterrent that was policing §3.1 by accident: it invalidated
/// every world ever generated, which is a visible, expensive, argued-about
/// event. Now it is a checklist — new `Domain`, new variant, regenerate
/// goldens. The seam is right (a world silently changing meaning is worse), but
/// it removed friction that a different invariant was relying on.
///
/// The `if physics >= V2 { score += w * term }` idiom makes it sharper: that is
/// monotone accretion inside `affinity()`, and two versions in, the scoring
/// function is a list of version-gated additive terms that all look alike.
/// "V2 physics has a term that helps membranes form" would be one more line
/// among them.
///
/// **So: a new `PhysicsVersion` must state the physical process it adds in
/// terms that name no biological structure.** "An environmental scalar enters
/// the fold energy" passes. "A rule that helps membranes form" fails on its
/// face, because it names its own outcome. That is §3.1's deletion test applied
/// to the justification rather than the code, and it is the thing that makes
/// this seam safe to have.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
#[non_exhaustive]
pub enum PhysicsVersion {
    /// Shape and surface character, per spec §8.3. Everything in V0 and V1.
    V1 = 1,
}

#[derive(Debug, Clone, PartialEq)]
pub struct Universe {
    pub seed: u64,
    /// The laws this universe was generated under. Never inferred from the
    /// running binary — a universe loaded from disk keeps the physics it was
    /// born with, or it is a different universe wearing the same name.
    pub physics: PhysicsVersion,
    pub shell: ShellPattern,
    pub elements: Vec<Element>,
    pub bonds: BondEnergyMatrix,
    pub consts: UniverseConsts,
}

impl Universe {
    #[must_use]
    pub fn generate(seed: u64) -> Self {
        // `generate_elements` returns the shell it actually used. An earlier
        // draft re-derived it by rebuilding the same stream and replaying —
        // which agreed by luck, and would silently stop agreeing the moment
        // anyone added a draw before the shell call inside `generate_elements`.
        // `Universe.shell` would then describe a table that does not exist,
        // with nothing failing. This is the class of bug dropping `Copy` on
        // `Stream` (Task 3) exists to surface.
        let (shell, elements) = element::generate_elements(seed);

        // A separate stream index so that adding a draw in element generation
        // cannot shift the constants, and vice versa.
        let mut rng = Stream::new(seed, Domain::Universe, 1);
        let bonds = BondEnergyMatrix::generate(&elements, &mut rng);

        // Solvent: a small, abundant, strongly-polar element. Picking from the
        // first third biases toward light elements without hardcoding one.
        let solvent_pool = (elements.len() / 3).max(1);
        let solvent = ElementId(rng.next_range(solvent_pool as u64) as u8);

        let temp_min = Thermal(rng.next_f64_range(180.0, 260.0));
        let temp_max = temp_min + Thermal(rng.next_f64_range(200.0, 500.0));

        let consts = UniverseConsts {
            ideal_gap: rng.next_f64_range(1.6, 2.8),
            w_shape: rng.next_f64_range(0.6, 1.4),
            w_charge: rng.next_f64_range(0.6, 1.4),
            rate_prefactor: rng.next_f64_range(1e3, 1e5),
            decay_scale: rng.next_f64_range(1e-6, 1e-4),
            solvent,
            temp_min,
            temp_max,
        };

        Self {
            seed,
            // Set at construction, never inferred from the running binary.
            // A universe reloaded under newer laws must keep the ones it was
            // born with, or `U-7F3A21C9` stops meaning what §6 promises.
            physics: PhysicsVersion::V1,
            shell,
            elements,
            bonds,
            consts,
        }
    }

    #[must_use]
    pub fn element(&self, id: ElementId) -> &Element {
        // Callers hold ids minted by this universe; an out-of-range id is a
        // programming error, so clamping keeps the type total without hiding
        // it behind an Option that every call site would have to unwrap.
        &self.elements[(id.0 as usize).min(self.elements.len() - 1)]
    }

    #[must_use]
    pub fn solvent(&self) -> &Element {
        self.element(self.consts.solvent)
    }
}

### Task 5b: Abundance from nucleosynthesis

**Files:** modify `crates/borbax-universe/src/element.rs`; test same file.

**Interfaces:** no signature change. `Element::abundance` keeps its type and its
meaning; only how it is computed changes.

**This is a deliberate physics change and a golden regeneration.** Both digests
move. It is its own task rather than part of Task 5 because Task 5 took six
review rounds against the current abundance, and a physics change landing
mid-review of a different one is how findings get measured against stale code.

## The mechanism

`abundance` is currently `exp(-units * decay)` — one drawn constant, strictly
monotone decreasing, no structure. It becomes the sum of four process
components, in the shape a real universe's element inventory is built:

1. **Primordial.** The overwhelming majority is the lightest element, with a
   secondary share at the second. Nothing heavier.
2. **Stellar fusion.** Each step up costs a step, so an ever-decreasing amount —
   **up to the point where fusion stops paying for itself.**
3. **Supernova.** Elements past that point, which fusion cannot reach, at a much
   smaller amplitude.
4. **Merger / r-process.** A chunk of the heaviest elements, from neutron-star
   mergers and similar events.

**The boundary between 2 and 3 is already derived and must not be drawn.**
`ShellPattern::peak` is read off the finished `energy_per_unit` series —
"where the per-unit binding energy peaks. **Read off the finished series, never
passed in**" — which is precisely "fusion costs more fuel than it generates".
That is what makes this shaped by the table rather than imposed on it, and it is
the single most important property of this task. Draw the amplitudes and the
decline rates; derive every boundary.

**Fidelity is shape-only.** No real abundance ratios, no calibration against our
universe's H/He margin — that would put real-world numbers in the generator,
which is nearer §5's line than anything currently in the crate. Two universes
must differ in character, not merely in noise.

## The recorded rejection this must not reproduce, and why it does not

`abundance`'s own doc records that a draft carried an `exp(beta *
energy_per_unit)` tilt at `beta = 0.6`, and that it was killed on measurement:
*"implementing the stated story makes the heaviest element the most abundant and
collapses `p_c` to 0.112"*. That is a different mechanism — a Boltzmann tilt
toward binding energy — and this is a sum of process components in which
primordial dominates by construction and the r-process contribution is a chunk
rather than a peak. **The failure mode is avoided by construction, and the test
that caught it must be re-run anyway**, because `abundance` is §7.2's gel lever
and CLAUDE.md names the decay band as the first thing to suspect when a run
produces nothing.

## What this interacts with

Task 5's review measured that the bond matrix is exactly rank 1 and its single
ranking is **98.86% concordant with atom count** — "bigger is stronger", where
the previous derivation had an interior peak. The standing argument that this is
harmless is *"large elements are rare anyway, because abundance falls
geometrically"*. **An r-process bump weakens exactly that argument**, so this
task must re-measure it rather than inherit the conclusion.

## Decided: fix the cause, do not work around it

**The monomer is inert because of where the shell loop starts counting, not
because of anything geometric.** `generate_elements` initialises `filled = 1`,
declaring the lone central unit to be a *complete shell 0 of capacity 1*. So
`outer == 0`, the valence rule reads that as a closure, and a closure has no
frontier. But a lone sphere has its entire surface available to bond; calling it
closed is an artefact of the loop's initial condition.

The real analogy makes this obvious. Hydrogen is reactive because its shell holds
**2** and it has **1** — half filled, one bond to give. Helium holds 2 in 2 and
is inert. Borbax currently models its first element as helium when it should be
hydrogen.

**The model already gives the right answer once it counts correctly.** Treat the
lone unit as `outer == 1` in shell 1 (capacity `k + 2`) rather than as a closed
shell 0, and `elements_one_past_a_closure_all_have_valence_one` — an existing,
reviewed assertion — says the monomer gets **valence 1**. Exactly hydrogen. No
new rule, no special case: the same derivation every other element obeys, applied
to an element the loop had excluded from it.

**This is the third face of an already-open defect.** `contacts_upto(1) = 0`,
`energy_per_unit(1) = -sigma`, `deficit(1) > 1` — all recorded as "the monomer is
a degenerate case", all with this root. Fixing the counting addresses the class,
not one symptom.

**Explicitly rejected: drawing the first element's valence.** It was raised and
is the `peak`-as-a-parameter shape exactly — a chosen number producing behaviour
that would later be reported as emergent. The variation it was reaching for
already exists one level up: shell 1 holds `k + 2` units with `k` drawn 6..=14,
so **the first period is 8 to 16 elements long**, which moves the first closure,
the inert set and the binding peak. Two universes already differ in the shape of
their periodic table. If more first-period variation is wanted, the honest lever
is the shell law's `+2` — currently forced by "shell 1 *is* the units touching
the core" — not an override on one atom.

**Cost, stated so it is not discovered in Step 4.** Changing where shells start
moves every element's `period`, `group`, `valence`, `affinity`, `outer_fill_band`
and mass defect, and therefore the binding peak, `abundance`, every bond energy
and both digests. It is the largest single physics change since Task 4. It lands
here rather than separately because Task 5b must otherwise *work around* the
inert monomer while designing an abundance profile that concentrates matter on
it — and the workaround would be the defect, preserved.

*Discriminator:* the monomer's valence must be **1**, derived by the same
`frontier_notches` path as every other element, with no branch on `units == 1`
anywhere in `generate_elements`. A fix that special-cases the first element has
reintroduced what it removed.

## The consequence this fix removes, kept for the record

**Measured over 200 universes: the monomer can bond in 0 of them, and the
lightest bondable element is `units == 2` in every seed.** At `units == 1` there
is no incomplete outer shell, so no frontier, so `valence == 0`. That is correct
and G3-compliant — it is the *opposite* of hydrogen, which is the kind of
structural unlikeness §5 wants — but it collides with the profile above.

In our universe the overwhelmingly abundant element is also the primary bonding
partner. In Borbax it is a noble gas. Under the current flat
`exp(-units * decay)`, inert elements hold a mean **12.05%** of total abundance.
Under a primordial spike they would hold something closer to half or more, and
**§7.2's gel lever counts bonds per node** — nodes that cannot bond at all are
not a small correction to `p_c`, they are a different graph.

Three ways to go, and the task must pick one explicitly rather than discover it
in Task 18:

1. **Accept it.** A large inert reservoir with the chemistry running in the
   minority is a legitimate universe, and arguably a more interesting one — it
   makes the reactive fraction a resource rather than a given. Requires
   re-deriving §7.2's `p_c` over the *bondable* subgraph rather than the whole
   table, which is a change to how the gel lever is measured.
2. **Put the primordial peak on the lightest bondable element** (`units == 2`)
   rather than `units == 1`. Small shift, preserves the story — "the first thing
   fusion makes that can react" — and keeps the abundant species chemically live.
   The monomer then behaves as a genuinely trace inert gas.
3. **Reconsider `valence` at `units == 1`.** Rejected in advance: it falls out of
   "a closed shell has no frontier", which is load-bearing for the whole valence
   derivation and for §7.1's periodicity story. Do not fix the profile by
   breaking the packing.

*Discriminator, whichever is chosen:* the share of total abundance held by
`valence == 0` elements must be **measured and asserted**, not left to fall out.
It is currently 12.05% and nothing watches it.

```rust
//! Small-molecule atom graphs (spec §8.1).
//!
//! Capped at twelve atoms, which lets the whole molecule live in 72 bytes
//! with adjacency stored as bitset rows. That matters more than it might
//! appear: colour refinement in `canonical.rs` becomes a sequence of
//! popcounts over masks, with no allocation and no hashing anywhere in the
//! hot path.

use borbax_units::Mass;
use borbax_universe::{ElementId, Universe};

pub const MAX_ATOMS: usize = 12;
/// Bond orders 1, 2, 3 — one bitset plane each.
pub const N_ORDERS: usize = 3;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub struct Mol12 {
    pub n: u8,
    pub elem: [u8; MAX_ATOMS],
    /// `adj[order - 1][i]` is a bitset of atoms bonded to `i` at that order.
    pub adj: [[u16; MAX_ATOMS]; N_ORDERS],
}

impl Default for Mol12 {
    fn default() -> Self {
        Self::new()
    }
}

impl Mol12 {
    #[must_use]
    pub const fn new() -> Self {
        Self { n: 0, elem: [0; MAX_ATOMS], adj: [[0; MAX_ATOMS]; N_ORDERS] }
    }

    /// Append an atom. Silently ignored at capacity — a molecule that cannot
    /// grow is chemically meaningful (it simply does not react that way),
    /// whereas a panic here would take down a simulation step.
    pub fn add_atom(&mut self, e: ElementId) -> Option<u8> {
        if self.n as usize >= MAX_ATOMS {
            return None;
        }
        let idx = self.n;
        self.elem[idx as usize] = e.0;
        self.n += 1;
        Some(idx)
    }

    /// Add or replace a bond. Orders outside 1..=3 are ignored.
    pub fn add_bond(&mut self, a: u8, b: u8, order: u8) {
        if a == b || a >= self.n || b >= self.n || !(1..=3).contains(&order) {
            return;
        }
        self.clear_bond(a, b);
        let plane = (order - 1) as usize;
        self.adj[plane][a as usize] |= 1 << b;
        self.adj[plane][b as usize] |= 1 << a;
    }

    pub fn clear_bond(&mut self, a: u8, b: u8) {
        for plane in &mut self.adj {
            plane[a as usize] &= !(1 << b);
            plane[b as usize] &= !(1 << a);
        }
    }

    #[must_use]
    pub fn bond_order(&self, a: u8, b: u8) -> u8 {
        for (i, plane) in self.adj.iter().enumerate() {
            if plane[a as usize] & (1 << b) != 0 {
                return i as u8 + 1;
            }
        }
        0
    }

    /// Number of bonded neighbours, regardless of order.
    #[must_use]
    pub fn degree(&self, a: u8) -> u32 {
        self.neighbours(a).count_ones()
    }

    /// Bitset of all neighbours of `a` at any order.
    #[must_use]
    pub fn neighbours(&self, a: u8) -> u16 {
        self.adj.iter().fold(0, |acc, plane| acc | plane[a as usize])
    }

    /// Total valence consumed by bonds, counting order.
    #[must_use]
    pub fn valence_used(&self, a: u8) -> u32 {
        self.adj
            .iter()
            .enumerate()
            .map(|(i, plane)| (i as u32 + 1) * plane[a as usize].count_ones())
            .sum()
    }

    /// Exact total mass. Integer addition, so this is a guarantee rather
    /// than a tolerance (spec §13.1).
    #[must_use]
    pub fn mass(&self, u: &Universe) -> Mass {
        (0..self.n).map(|i| u.element(ElementId(self.elem[i as usize])).mass).sum()
    }

    #[must_use]
    pub fn is_connected(&self) -> bool {
        if self.n == 0 {
            return true;
        }
        let mut seen: u16 = 1;
        let mut frontier: u16 = 1;
        while frontier != 0 {
            let mut next: u16 = 0;
            for i in 0..self.n {
                if frontier & (1 << i) != 0 {
                    next |= self.neighbours(i);
                }
            }
            next &= !seen;
            seen |= next;
            frontier = next;
        }
        seen.count_ones() == u32::from(self.n)
    }
}
```

```rust
//! Canonical labelling, so isomorphic molecules intern to the same species.
//!
//! Colour refinement (1-WL) followed by individualization-refinement, taking
//! the lexicographically smallest encoding. At twelve atoms with element and
//! bond-order labels, refinement alone discretises the colouring for the
//! large majority of molecules, so the search is a rarely-taken path — see
//! `search_rarely_needs_to_branch`, which measures this rather than assuming.

use crate::graph::{Mol12, MAX_ATOMS, N_ORDERS};

/// Upper-triangle pair count for 12 vertices: 12 * 11 / 2 = 66, which fits
/// one `u128` per bond order with room to spare. Three planes rather than a
/// packed 2-bit encoding because 66 * 2 = 132 bits does not fit, and because
/// three planes compare faster than one 132-bit value would.
const N_PAIRS: usize = MAX_ATOMS * (MAX_ATOMS - 1) / 2;

/// Ceiling on leaves explored by the individualization search.
///
/// Valence caps degree in any chemically reachable molecule, which bounds
/// the automorphism group far below this. Hitting the cap therefore means a
/// molecule was constructed that chemistry cannot produce, and the right
/// response is to investigate the construction — **not** to raise the cap.
/// If it is ever hit legitimately, bind to nauty (spec §18.2) rather than
/// growing this search.
pub const SEARCH_LEAF_CAP: u32 = 50_000;

#[derive(Debug, Clone, Copy, Default, PartialEq, Eq)]
pub struct SearchStats {
    pub leaves: u32,
    pub refinement_rounds: u32,
    /// Set when the search hit `SEARCH_LEAF_CAP` and returned a **partial**
    /// minimum. That is not a slow answer, it is a wrong one: the same
    /// molecule under a different labelling can explore a different prefix and
    /// produce a different canonical form, so it interns as a second species.
    /// Sticky so callers cannot miss it.
    pub cap_hit: bool,
}

/// A molecule's canonical encoding. Comparison is a few integer compares,
/// which is what makes this usable as an intern key.
///
/// Field order defines the derived `Ord`, and therefore defines which
/// labelling counts as "smallest". It is part of the physics: changing it
/// changes every species id and every golden hash.
#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Hash)]
pub struct CanonForm {
    pub n: u8,
    pub elem: [u8; MAX_ATOMS],
    pub planes: [u128; N_ORDERS],
}

#[inline]
fn pair_bit(i: usize, j: usize) -> u32 {
    // Canonical index for the unordered pair {i, j} with i < j.
    let (lo, hi) = if i < j { (i, j) } else { (j, i) };
    (hi * (hi - 1) / 2 + lo) as u32
}

/// Encode a molecule under a given vertex ordering.
/// `order[k]` is the original vertex placed at canonical position `k`.
fn encode(m: &Mol12, order: &[u8]) -> CanonForm {
    let mut elem = [0u8; MAX_ATOMS];
    let mut planes = [0u128; N_ORDERS];
    for (k, &v) in order.iter().enumerate() {
        elem[k] = m.elem[v as usize];
    }
    for a in 0..order.len() {
        for b in (a + 1)..order.len() {
            let o = m.bond_order(order[a], order[b]);
            if o > 0 {
                planes[(o - 1) as usize] |= 1u128 << pair_bit(a, b);
            }
        }
    }
    CanonForm { n: m.n, elem, planes }
}

/// One round of colour refinement. Returns the number of colour classes.
///
/// A vertex's signature under the current colouring is its own colour plus,
/// for every (bond order, colour) pair, how many neighbours it has of that
/// colour — all computed as popcounts over colour masks. No allocation, no
/// hashing, and no map iteration whose order could vary.
fn refine(m: &Mol12, colour: &mut [u8; MAX_ATOMS], stats: &mut SearchStats) -> usize {
    let n = m.n as usize;
    if n == 0 {
        return 0;
    }
    loop {
        stats.refinement_rounds += 1;
        let n_colours = usize::from(*colour[..n].iter().max().unwrap_or(&0)) + 1;

        let mut masks = [0u16; MAX_ATOMS];
        for v in 0..n {
            masks[colour[v] as usize] |= 1 << v;
        }

        // Signature per vertex: own colour, then counts per (order, colour).
        let mut sig = [[0u8; 1 + N_ORDERS * MAX_ATOMS]; MAX_ATOMS];
        for v in 0..n {
            sig[v][0] = colour[v];
            let mut k = 1;
            for plane in &m.adj {
                for c in 0..n_colours {
                    sig[v][k] = (plane[v] & masks[c]).count_ones() as u8;
                    k += 1;
                }
            }
        }

        // Rank signatures to produce new colours. Insertion-order-free: the
        // rank of a signature is how many distinct signatures are strictly
        // smaller, which depends only on the multiset of signatures.
        let mut new_colour = [0u8; MAX_ATOMS];
        for v in 0..n {
            let mut rank = 0u8;
            for w in 0..n {
                if sig[w] < sig[v] {
                    // Count distinct smaller signatures only.
                    if !(0..w).any(|x| sig[x] == sig[w]) {
                        rank += 1;
                    }
                }
            }
            new_colour[v] = rank;
        }

        let before = count_classes(colour, n);
        let after = count_classes(&new_colour, n);
        *colour = new_colour;
        if after == before {
            return after;
        }
    }
}

fn count_classes(colour: &[u8; MAX_ATOMS], n: usize) -> usize {
    let mut seen = 0u16;
    for v in 0..n {
        seen |= 1 << colour[v];
    }
    seen.count_ones() as usize
}

/// Reduce a molecule to its canonical form.
///
/// Returns the form plus search statistics, which exist so the branch rate
/// can be measured rather than assumed.
#[must_use]
pub fn canonicalise(m: &Mol12) -> (CanonForm, SearchStats) {
    let n = m.n as usize;
    let mut stats = SearchStats::default();
    if n == 0 {
        return (CanonForm { n: 0, elem: [0; MAX_ATOMS], planes: [0; N_ORDERS] }, stats);
    }

    // Initial colouring by element, **densified**.
    //
    // Assigning `colour[v] = m.elem[v]` directly is wrong and fails silently.
    // Element ids run to 119, while `refine`'s `masks` is `[u16; MAX_ATOMS]`,
    // its `sig` rows are sized for at most `MAX_ATOMS` colours, and
    // `count_classes` computes `1u16 << colour[v]` — which panics in debug and
    // **masks the shift** in release, so refinement stops before it is stable
    // and two relabellings of the same molecule intern as different species.
    //
    // Every test in this task uses `ElementId(0..5)`, so all of them pass.
    // Ranking the ids makes every colour dense in `0..n`, which is what the
    // three arrays are actually sized for.
    let mut colour = [0u8; MAX_ATOMS];
    for v in 0..n {
        // Rank of this element among the distinct elements present. Depends
        // only on the multiset of element ids, so it stays isomorphism-invariant.
        let mut rank = 0u8;
        for w in 0..n {
            if m.elem[w] < m.elem[v] && !(0..w).any(|x| m.elem[x] == m.elem[w]) {
                rank += 1;
            }
        }
        colour[v] = rank;
    }
    debug_assert!(colour[..n].iter().all(|&c| (c as usize) < MAX_ATOMS));
    let mut best: Option<CanonForm> = None;
    search(m, colour, &mut best, &mut stats);
    // `search` always reaches at least one leaf for n > 0.
    let form = best.unwrap_or_else(|| encode(m, &(0..m.n).collect::<Vec<u8>>()));
    (form, stats)
}

fn search(m: &Mol12, mut colour: [u8; MAX_ATOMS], best: &mut Option<CanonForm>, stats: &mut SearchStats) {
    let n = m.n as usize;
    if stats.leaves >= SEARCH_LEAF_CAP {
        // Returning here yields a partial minimum, which is a *wrong* canonical
        // form rather than a slow one — see `SearchStats::cap_hit`.
        stats.cap_hit = true;
        debug_assert!(false, "canonicalisation hit the leaf cap: the molecule is not valence-legal, or the cap is wrong");
        return;
    }
    let classes = refine(m, &mut colour, stats);

    if classes == n {
        // Discrete: the colouring *is* an ordering.
        stats.leaves += 1;
        let mut order = vec![0u8; n];
        for v in 0..n {
            order[colour[v] as usize] = v as u8;
        }
        let form = encode(m, &order);
        if best.as_ref().is_none_or(|b| form < *b) {
            *best = Some(form);
        }
        return;
    }

    // Target cell: the smallest colour class with more than one member.
    // Deterministic choice — "smallest colour, then lowest index" — so the
    // search tree is identical on every platform.
    let mut target = u8::MAX;
    for c in 0..=u8::MAX {
        let members: Vec<usize> = (0..n).filter(|&v| colour[v] == c).collect();
        if members.len() > 1 {
            target = c;
            break;
        }
        if c == u8::MAX {
            break;
        }
    }
    if target == u8::MAX {
        return;
    }

    for v in 0..n {
        if colour[v] != target {
            continue;
        }
        // Individualize v: it keeps the target colour, everyone else in the
        // cell (and every higher colour) shifts up by one.
        let mut c2 = colour;
        for w in 0..n {
            if c2[w] > target || (c2[w] == target && w != v) {
                c2[w] += 1;
            }
        }
        search(m, c2, best, stats);
    }
}
```

```rust
//! Sample directions on a sphere, and the rotations that permute them
//! (spec §8.2).
//!
//! The directions are vertices of a subdivided icosahedron. That choice is
//! not aesthetic: the icosahedral rotation group has 60 elements and every
//! one maps the vertex set exactly onto itself, so **a rotation is a
//! permutation** — a lookup, not an interpolation. With arbitrary sample
//! directions, rotating a signature would mean resampling, and the resulting
//! error would land squarely on the comparison that decides whether two
//! molecules bind.
//!
//! Built once and passed by reference. Deliberately not a global: global
//! state is one more thing that can differ between a test and a run.

/// Order of the icosahedral rotation group. Reflections are excluded — see
/// spec §22.8, which makes Borbax chemistry handed on purpose.
pub const N_ROTATIONS: usize = 60;

#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum GeoError {
    /// D must be one of the geodesic ladder values: 12, 42, 162.
    UnsupportedResolution(usize),
    /// A rotation failed to map the vertex set onto itself. This would mean
    /// the symmetry assumption above is broken, which is a bug, not input.
    RotationNotClosed,
}

/// Vertices produced by subdividing an icosahedron `level` times.
#[must_use]
pub const fn vertex_count(level: u32) -> usize {
    // 10 * 4^level + 2
    10 * 4usize.pow(level) + 2
}

const fn level_for(d: usize) -> Option<u32> {
    match d {
        12 => Some(0),
        42 => Some(1),
        162 => Some(2),
        _ => None,
    }
}

#[derive(Debug, Clone)]
pub struct Geodesic<const D: usize> {
    /// Unit sample directions, in a canonical order.
    pub dirs: [[f64; 3]; D],
    /// `perms[r][i] = j` means rotation `r` carries direction `i` to `j`.
    pub perms: [[u8; D]; N_ROTATIONS],
    /// `anti[i] = j` where `dirs[j] == -dirs[i]`.
    ///
    /// **Required by the binding kernel** (§8.3). Two bodies in contact touch
    /// along opposite directions, so `affinity` indexes its partner through
    /// `anti[perm[r][i]]`. Omitting it converts the search into the 60
    /// *improper* elements of the icosahedral group — reflections only, the
    /// opposite of §22.8 — and nothing fails to signal it.
    ///
    /// The vertex set is antipodally closed at every subdivision level, so
    /// this is total; `build_anti` errors rather than approximating if it
    /// ever is not.
    pub anti: [u8; D],
}

type Vec3 = [f64; 3];

fn sub(a: Vec3, b: Vec3) -> Vec3 {
    [a[0] - b[0], a[1] - b[1], a[2] - b[2]]
}
fn dot(a: Vec3, b: Vec3) -> f64 {
    a[0] * b[0] + a[1] * b[1] + a[2] * b[2]
}
fn cross(a: Vec3, b: Vec3) -> Vec3 {
    [a[1] * b[2] - a[2] * b[1], a[2] * b[0] - a[0] * b[2], a[0] * b[1] - a[1] * b[0]]
}
fn scale(a: Vec3, s: f64) -> Vec3 {
    [a[0] * s, a[1] * s, a[2] * s]
}
fn normalise(a: Vec3) -> Vec3 {
    let n = dot(a, a).sqrt();
    if n == 0.0 { a } else { scale(a, 1.0 / n) }
}
fn dist2(a: Vec3, b: Vec3) -> f64 {
    let d = sub(a, b);
    dot(d, d)
}

/// The twelve icosahedron vertices, from the golden ratio.
fn icosahedron() -> Vec<Vec3> {
    let phi = (1.0 + 5.0f64.sqrt()) / 2.0;
    let mut v = Vec::with_capacity(12);
    for &s1 in &[1.0, -1.0] {
        for &s2 in &[1.0, -1.0] {
            v.push([0.0, s1, s2 * phi]);
            v.push([s1, s2 * phi, 0.0]);
            v.push([s1 * phi, 0.0, s2]);
        }
    }
    v.into_iter().map(normalise).collect()
}

/// Faces derived rather than hardcoded: on an icosahedron, a face is exactly
/// a triple of mutually-adjacent vertices, and adjacency is "at the minimum
/// pairwise distance". Deriving avoids a 20-row table that is easy to get
/// subtly wrong and impossible to spot by reading.
fn faces_of(v: &[Vec3]) -> Vec<[usize; 3]> {
    let mut min_d2 = f64::MAX;
    for i in 0..v.len() {
        for j in (i + 1)..v.len() {
            min_d2 = min_d2.min(dist2(v[i], v[j]));
        }
    }
    let adjacent = |a: usize, b: usize| (dist2(v[a], v[b]) - min_d2).abs() < 1e-9;

    let mut out = Vec::new();
    for i in 0..v.len() {
        for j in (i + 1)..v.len() {
            for k in (j + 1)..v.len() {
                if adjacent(i, j) && adjacent(j, k) && adjacent(i, k) {
                    out.push([i, j, k]);
                }
            }
        }
    }
    out
}

/// Find `p` in `verts`, or append it. Linear scan is fine at D <= 162 and
/// avoids any hashing whose iteration order could vary.
fn intern(verts: &mut Vec<Vec3>, p: Vec3) -> usize {
    for (i, q) in verts.iter().enumerate() {
        if dist2(*q, p) < 1e-18 {
            return i;
        }
    }
    verts.push(p);
    verts.len() - 1
}

impl<const D: usize> Geodesic<D> {
    pub fn build() -> Result<Self, GeoError> {
        let level = level_for(D).ok_or(GeoError::UnsupportedResolution(D))?;

        let base = icosahedron();
        let mut verts = base.clone();
        let mut faces = faces_of(&base);

        for _ in 0..level {
            let mut next = Vec::with_capacity(faces.len() * 4);
            for f in &faces {
                // Midpoints are computed into locals first. Writing them
                // inline as arguments to `intern(&mut verts, ...)` borrows
                // `verts` immutably inside a call that already borrows it
                // mutably — E0502, since two-phase borrows do not cover
                // explicit `&mut` arguments.
                let mid = |a: Vec3, b: Vec3| normalise([(a[0] + b[0]) * 0.5, (a[1] + b[1]) * 0.5, (a[2] + b[2]) * 0.5]);
                let (p0, p1, p2) = (verts[f[0]], verts[f[1]], verts[f[2]]);
                let (m01, m12, m20) = (mid(p0, p1), mid(p1, p2), mid(p2, p0));
                let m = [
                    intern(&mut verts, m01),
                    intern(&mut verts, m12),
                    intern(&mut verts, m20),
                ];
                next.push([f[0], m[0], m[2]]);
                next.push([m[0], f[1], m[1]]);
                next.push([m[2], m[1], f[2]]);
                next.push([m[0], m[1], m[2]]);
            }
            faces = next;
        }

        if verts.len() != D {
            return Err(GeoError::UnsupportedResolution(D));
        }

        // Canonical ordering. `total_cmp` gives a total order on f64 with no
        // tolerance and no platform variation, so the resulting index
        // assignment is identical everywhere (spec §13.4).
        verts.sort_by(|a, b| {
            a[2].total_cmp(&b[2]).then(a[1].total_cmp(&b[1])).then(a[0].total_cmp(&b[0]))
        });

        let mut dirs = [[0.0; 3]; D];
        dirs.copy_from_slice(&verts);

        let perms = Self::build_perms(&dirs)?;
        let anti = Self::build_anti(&dirs)?;
        Ok(Self { dirs, perms, anti })
    }

    /// Index of `-dirs[i]` for every `i`.
    fn build_anti(dirs: &[[f64; 3]; D]) -> Result<[u8; D], GeoError> {
        let mut anti = [0u8; D];
        for i in 0..D {
            let target = [-dirs[i][0], -dirs[i][1], -dirs[i][2]];
            let mut best = (usize::MAX, f64::MAX);
            for j in 0..D {
                let d = dist2(target, dirs[j]);
                if d < best.1 {
                    best = (j, d);
                }
            }
            // Must land exactly on a sample direction. A loose match would mean
            // the vertex set is not antipodally closed, which would silently
            // corrupt every binding comparison rather than failing visibly.
            if best.1 > 1e-24 {
                return Err(GeoError::RotationNotClosed);
            }
            anti[i] = best.0 as u8;
        }
        Ok(anti)
    }

    /// Build the 60 rotations as permutations of `dirs`.
    ///
    /// Construction: pick a reference icosahedron vertex and one of its
    /// neighbours. For every (vertex, neighbour) pair there is exactly one
    /// rotation carrying the reference pair onto it, giving 12 x 5 = 60.
    fn build_perms(dirs: &[[f64; 3]; D]) -> Result<[[u8; D]; N_ROTATIONS], GeoError> {
        let base = icosahedron();
        // Reference frame from vertex 0 and its lowest-indexed neighbour.
        let mut min_d2 = f64::MAX;
        for i in 0..base.len() {
            for j in (i + 1)..base.len() {
                min_d2 = min_d2.min(dist2(base[i], base[j]));
            }
        }
        let neighbours = |a: usize| -> Vec<usize> {
            (0..base.len()).filter(|&b| b != a && (dist2(base[a], base[b]) - min_d2).abs() < 1e-9).collect()
        };

        // Orthonormal frame from an axis and a second direction.
        let frame = |v: Vec3, w: Vec3| -> [Vec3; 3] {
            let e0 = normalise(v);
            let e1 = normalise(sub(w, scale(e0, dot(w, e0))));
            let e2 = cross(e0, e1);
            [e0, e1, e2]
        };

        let f0 = frame(base[0], base[neighbours(0)[0]]);
        let mut perms = [[0u8; D]; N_ROTATIONS];
        let mut r = 0usize;

        for v in 0..base.len() {
            for &w in &neighbours(v) {
                if r >= N_ROTATIONS {
                    return Err(GeoError::RotationNotClosed);
                }
                let f = frame(base[v], base[w]);
                // R = F * F0^T, applied as: express in F0's basis, rebuild in F's.
                let apply = |p: Vec3| -> Vec3 {
                    let c = [dot(p, f0[0]), dot(p, f0[1]), dot(p, f0[2])];
                    [
                        c[0] * f[0][0] + c[1] * f[1][0] + c[2] * f[2][0],
                        c[0] * f[0][1] + c[1] * f[1][1] + c[2] * f[2][1],
                        c[0] * f[0][2] + c[1] * f[1][2] + c[2] * f[2][2],
                    ]
                };

                for i in 0..D {
                    let p = apply(dirs[i]);
                    let mut best = (usize::MAX, f64::MAX);
                    for j in 0..D {
                        let d = dist2(p, dirs[j]);
                        if d < best.1 {
                            best = (j, d);
                        }
                    }
                    // The rotation must land *on* a sample direction. A loose
                    // match would mean the symmetry assumption is false, which
                    // would silently corrupt every signature comparison.
                    if best.1 > 1e-12 {
                        return Err(GeoError::RotationNotClosed);
                    }
                    perms[r][i] = best.0 as u8;
                }
                r += 1;
            }
        }

        if r != N_ROTATIONS {
            return Err(GeoError::RotationNotClosed);
        }
        Ok(perms)
    }
}
```

**From the Task 2 review — a live hazard in the code this task lifts from.**
`experiments/src/embed.rs` picks SMACOF's landmark pivots with `max_by` over
`graph_distances`, which returns `f64::INFINITY` for an unreachable atom. It is
safe in `experiments` only because the test molecules are random trees. On a
graph with a disconnected component the pivots become infinite, stress hits
`inf - inf`, the whole embedding goes NaN, and NaN then wins every downstream
selection — a species with a garbage signature and a garbage affinity, with
nothing failing anywhere. Guard it here: either `graph_distances` returns a
`Result` on a disconnected input, or `embed` asserts finiteness before the
pivot selection. The distinguishing test is a two-component graph asserting the
result is an error or entirely finite; add a two-atom molecule and a path graph
while you are there, since those are the other degenerate SMACOF inputs.

**And decide the `Span` question below before writing `Signature`, because
retrofitting it afterwards is a much larger diff.**

Every length in the geometric core is currently planned as a bare `f64` —
`Signature.r`, `BindConsts::ideal_gap`, the cavity `SHELL`, `LATTICE_SPAN` —
while `Element::radius` is already a `Span` that gets `.get()`-ed at the first
arithmetic site. So the one dimension where a unit mix-up has already happened
*twice in this project* is the one passing through untyped:

- **G1**, still open: `ideal_gap` is on the wrong length scale, so binding is
  ~93% size and ~7% shape — complementarity never selects anything.
- The chemistry plan's own cavity comment describes the same bug in the past
  tense: adding raw grid integers to atom radii and comparing against
  `ideal_gap`, "two incommensurable numbers".

Both would have been compile errors with `Span`. `a` (surface character) stays
`f64` — it is genuinely dimensionless. Note `ds * ds` will not type-check once
`ds` is a `Span`, which is correct: a squared length is a different quantity,

```rust
//! 3D embedding by stress majorization (spec §8.2).
//!
//! Laplacian eigenvectors were the obvious choice and are wrong: eigenvectors
//! have arbitrary sign, and degenerate eigenvalues are common in the small
//! symmetric graphs molecules actually are, leaving the basis arbitrary. Since
//! the signature keys species identity and the fold cache, that arbitrariness
//! would land exactly where it does most damage. Stress majorization from a
//! deterministic start sidesteps the problem rather than managing it.
//!
//! No randomness is used at all — the initial placement is a function of the
//! atom index, so the result depends only on the molecule.

use crate::graph::{Mol12, MAX_ATOMS};
use borbax_universe::{ElementId, Universe};

/// Fixed iteration count. Not a convergence test: a tolerance-based stop
/// would make the result depend on floating-point details that vary in the
/// last bits, and §13.4 requires the same answer on every platform.
const ITERATIONS: usize = 240;

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Embedding {
    pub n: usize,
    pub pos: [[f64; 3]; MAX_ATOMS],
}

impl Embedding {
    /// RMS distance from the centroid — the molecule's own length scale,
    /// used to express displacements as fractions rather than absolutes.
    #[must_use]
    pub fn radius_of_gyration(&self) -> f64 {
        if self.n == 0 {
            return 0.0;
        }
        let s: f64 = self.pos[..self.n].iter().map(|p| p[0] * p[0] + p[1] * p[1] + p[2] * p[2]).sum();
        (s / self.n as f64).sqrt()
    }
}

/// All-pairs shortest path by BFS. n <= 12, so this is trivially cheap and
/// there is no reason to reach for anything cleverer.
fn hop_distances(m: &Mol12) -> [[u8; MAX_ATOMS]; MAX_ATOMS] {
    let n = m.n as usize;
    let mut d = [[u8::MAX; MAX_ATOMS]; MAX_ATOMS];
    for s in 0..n {
        d[s][s] = 0;
        let mut frontier: u16 = 1 << s;
        let mut seen: u16 = frontier;
        let mut depth = 0u8;
        while frontier != 0 {
            depth += 1;
            let mut next: u16 = 0;
            for v in 0..n {
                if frontier & (1 << v) != 0 {
                    next |= m.neighbours(v as u8);
                }
            }
            next &= !seen;
            seen |= next;
            for v in 0..n {
                if next & (1 << v) != 0 {
                    d[s][v] = depth;
                }
            }
            frontier = next;
        }
    }
    // Disconnected pairs: treat as one hop beyond the graph's diameter so
    // fragments are pushed apart without the solver seeing an infinity.
    let diameter = d.iter().flatten().filter(|x| **x != u8::MAX).copied().max().unwrap_or(1);
    for row in d.iter_mut().take(n) {
        for cell in row.iter_mut().take(n) {
            if *cell == u8::MAX {
                *cell = diameter.saturating_add(1);
            }
        }
    }
    d
}

#[must_use]
pub fn embed(m: &Mol12, u: &Universe) -> Embedding {
    let n = m.n as usize;
    let mut pos = [[0.0f64; 3]; MAX_ATOMS];
    if n == 0 {
        return Embedding { n: 0, pos };
    }
    if n == 1 {
        return Embedding { n: 1, pos };
    }

    // Target distance for one bond: the sum of the two atoms' radii, so
    // bigger atoms genuinely take up more room.
    let radius = |i: usize| u.element(ElementId(m.elem[i])).radius.get();
    let hops = hop_distances(m);
    let mut target = [[0.0f64; MAX_ATOMS]; MAX_ATOMS];
    for i in 0..n {
        for j in 0..n {
            if i != j {
                target[i][j] = f64::from(hops[i][j]) * (radius(i) + radius(j));
            }
        }
    }

    // Deterministic start. Spreads atoms out so the solver does not begin in
    // a degenerate configuration; any fixed start works.
    //
    // No trigonometry: a spiral needs `cos`/`sin`, which are platform-
    // dependent (§13.1), and the start does not need to be a good sphere —
    // only spread out and reproducible. These rational offsets are neither
    // collinear nor coplanar, which is all the solver requires.
    const START: [[f64; 3]; MAX_ATOMS] = [
        [1.0, 0.0, 0.0], [-1.0, 0.25, 0.5], [0.25, 1.0, -0.5], [-0.5, -1.0, 0.25],
        [0.5, 0.25, 1.0], [-0.25, 0.5, -1.0], [1.0, -0.75, -0.25], [-1.0, -0.5, 0.75],
        [0.75, 1.0, 0.5], [-0.75, 0.5, -1.0], [0.5, -1.0, 0.75], [-0.5, 0.75, 1.0],
    ];
    // Mean over *all* pairs, not row 0 — one atom's row is not the molecule's
    // length scale, and using it makes the start depend on which atom is first.
    let mut sum = 0.0;
    let mut cnt = 0.0;
    for i in 0..n {
        for j in 0..n {
            if i != j {
                sum += target[i][j];
                cnt += 1.0;
            }
        }
    }
    let mean_target = if cnt > 0.0 { sum / cnt } else { 1.0 };
    for i in 0..n {
        for k in 0..3 {
            pos[i][k] = START[i][k] * mean_target;
        }
    }

    // SMACOF. Weight 1/d^2 makes short (bonded) distances dominate, which is
    // what keeps local structure faithful while letting the global shape relax.
    let mut next = pos;
    for _ in 0..ITERATIONS {
        for i in 0..n {
            let mut num = [0.0f64; 3];
            let mut den = 0.0f64;
            for j in 0..n {
                if i == j {
                    continue;
                }
                let dij = target[i][j];
                if dij <= 0.0 {
                    continue;
                }
                let diff = [pos[i][0] - pos[j][0], pos[i][1] - pos[j][1], pos[i][2] - pos[j][2]];
                let dist = (diff[0] * diff[0] + diff[1] * diff[1] + diff[2] * diff[2]).sqrt().max(1e-9);
                let w = 1.0 / (dij * dij);
                for k in 0..3 {
                    num[k] += w * (pos[j][k] + dij * diff[k] / dist);
                }
                den += w;
            }
            if den > 0.0 {
                for k in 0..3 {
                    next[i][k] = num[k] / den;
                }
            }
        }
        pos = next;
    }

    // Centre on the centroid. Fixed summation order (spec §13.1).
    let mut c = [0.0f64; 3];
    for p in pos.iter().take(n) {
        for k in 0..3 {
            c[k] += p[k];
        }
    }
    for k in 0..3 {
        c[k] /= n as f64;
    }
    for p in pos.iter_mut().take(n) {
        for k in 0..3 {
            p[k] -= c[k];
        }
    }

    canonicalise_frame(&mut pos, n);
    Embedding { n, pos }
}

/// Rotate the embedding into a frame derived from the canonical atom order.
///
/// **Without this the shape is stable but the orientation is not**, and the
/// difference matters more than it sounds. Measured over 200 random tree
/// edits: aligned RMSD/R_g has median 0.13 — SMACOF does its job — but
/// *unaligned* displacement has median 0.74 and p90 1.34. Adding one atom
/// reorients the whole configuration by a generic rotation.
///
/// Canonicalising the signature over 60 rotations (§8.2) cannot absorb that:
/// it removes rotations *in the icosahedral group*, and a generic SO(3)
/// rotation sits up to ~44° from the nearest group element. So a one-atom
/// mutation would move the canonical signature by an amount dominated by an
/// arbitrary reorientation rather than by the shape change — mutation becomes
/// a random walk in signature space, neutral networks never form, and
/// `affinity` acquires a large pseudo-random component from two arbitrary
/// frames.
///
/// A straight chain does not show this, which is why the original
/// `chain(8) -> chain(9)` test passed at 0.45 while 135 of 200 random trees
/// exceeded the same threshold.
///
/// The frame is built from the lowest-indexed atoms that are non-degenerate,
/// and *which* atoms those are is part of the physics: the input must already
/// be in canonical order.
fn canonicalise_frame(pos: &mut [[f64; 3]; MAX_ATOMS], n: usize) {
    if n < 2 {
        return;
    }
    let norm = |v: [f64; 3]| (v[0] * v[0] + v[1] * v[1] + v[2] * v[2]).sqrt();
    let scale_by = 1.0f64.max(norm(pos[0]));

    // e0: first atom far enough from the centroid to define a direction.
    let Some(a0) = (0..n).find(|&i| norm(pos[i]) > 1e-9 * scale_by) else {
        return; // everything coincident; nothing to orient
    };
    let d0 = norm(pos[a0]);
    let e0 = [pos[a0][0] / d0, pos[a0][1] / d0, pos[a0][2] / d0];

    // e1: first atom not near-collinear with e0, orthogonalised against it.
    let mut e1 = [0.0f64; 3];
    let mut found = false;
    for i in 0..n {
        let p = pos[i];
        let dot = p[0] * e0[0] + p[1] * e0[1] + p[2] * e0[2];
        let perp = [p[0] - dot * e0[0], p[1] - dot * e0[1], p[2] - dot * e0[2]];
        let m = norm(perp);
        if m > 1e-9 * scale_by {
            e1 = [perp[0] / m, perp[1] / m, perp[2] / m];
            found = true;
            break;
        }
    }
    if !found {
        return; // collinear molecule; the axis alone is already canonical
    }
    let e2 = [
        e0[1] * e1[2] - e0[2] * e1[1],
        e0[2] * e1[0] - e0[0] * e1[2],
        e0[0] * e1[1] - e0[1] * e1[0],
    ];

    for p in pos.iter_mut().take(n) {
        let v = *p;
        *p = [
            v[0] * e0[0] + v[1] * e0[1] + v[2] * e0[2],
            v[0] * e1[0] + v[1] * e1[1] + v[2] * e1[2],
            v[0] * e2[0] + v[1] * e2[1] + v[2] * e2[2],
        ];
    }
}
```

```rust
//! The shape signature (spec §8.2) — the heart of the engine.
//!
//! A molecule reduces to two numbers per sample direction: how far its
//! surface extends that way, and what surface character faces that way.
//! Everything downstream — binding, catalysis, membranes, permeability — is
//! a comparison between two of these.

use crate::geodesic::{Geodesic, N_ROTATIONS};
use crate::graph::Mol12;
use crate::layout::Embedding;
use borbax_universe::{ElementId, Universe};

/// Width of the surface shell that contributes to surface character.
/// Atoms within this of the supporting plane are "facing" the direction.
const SHELL: f64 = 0.75;

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct Signature<const D: usize> {
    /// Surface extent per direction — the support function of the atom spheres.
    pub r: [f64; D],
    /// Summed surface character per direction, in [-1, 1].
    pub a: [f64; D],
}

impl<const D: usize> Signature<D> {
    #[must_use]
    pub fn zeroed() -> Self {
        Self { r: [0.0; D], a: [0.0; D] }
    }

    /// Apply a rotation, given as a permutation of directions.
    #[must_use]
    pub fn permuted(&self, perm: &[u8; D]) -> Self {
        let mut out = Self::zeroed();
        for i in 0..D {
            out.r[perm[i] as usize] = self.r[i];
            out.a[perm[i] as usize] = self.a[i];
        }
        out
    }

    /// The lexicographically smallest of this signature's 60 rotations.
    ///
    /// Without this the same molecule could produce different signatures
    /// depending on how its embedding happened to land, and species identity
    /// would stop being well-defined. `total_cmp` gives a total order on f64
    /// with no tolerance and no platform variation.
    #[must_use]
    pub fn canonicalise(&self, g: &Geodesic<D>) -> Self {
        let mut best = self.permuted(&g.perms[0]);
        for r in 1..N_ROTATIONS {
            let cand = self.permuted(&g.perms[r]);
            if cand.lex_cmp(&best) == std::cmp::Ordering::Less {
                best = cand;
            }
        }
        best
    }

    fn lex_cmp(&self, other: &Self) -> std::cmp::Ordering {
        for i in 0..D {
            match self.r[i].total_cmp(&other.r[i]) {
                std::cmp::Ordering::Equal => {}
                ord => return ord,
            }
        }
        for i in 0..D {
            match self.a[i].total_cmp(&other.a[i]) {
                std::cmp::Ordering::Equal => {}
                ord => return ord,
            }
        }
        std::cmp::Ordering::Equal
    }

    /// Rotation-invariant summary, used as a cheap pre-filter before the full
    /// binding search (spec §8.3). Any rotation permutes the extents, so the
    /// sorted multiset is unchanged.
    #[must_use]
    pub fn sorted_extents(&self) -> Vec<f64> {
        let mut v = self.r.to_vec();
        v.sort_by(f64::total_cmp);
        v
    }

    /// Euclidean distance in signature space. Used by the novelty metric and
    /// by the stability tests; not on any hot path.
    #[must_use]
    pub fn distance(&self, other: &Self) -> f64 {
        let mut acc = 0.0;
        for i in 0..D {
            acc += (self.r[i] - other.r[i]).powi(2) + (self.a[i] - other.a[i]).powi(2);
        }
        acc.sqrt()
    }
}

/// Build a signature from an embedded molecule.
///
/// `r` is the support function of the union of atom spheres: the furthest the
/// surface reaches in each direction. `a` is the surface character averaged
/// over the atoms that actually face that way, weighted linearly by how close
/// they sit to the supporting plane.
///
/// The weighting is deliberately polynomial rather than an exponential
/// falloff: `exp` is not portable between platform libm implementations
/// (spec §13.1), and a linear shell gives the same qualitative behaviour
/// with no reproducibility risk.
#[must_use]
pub fn signature<const D: usize>(
    m: &Mol12,
    e: &Embedding,
    g: &Geodesic<D>,
    u: &Universe,
) -> Signature<D> {
    let mut out = Signature::<D>::zeroed();
    if e.n == 0 {
        return out;
    }

    for d in 0..D {
        let dir = g.dirs[d];

        // Support function: the furthest any atom's surface reaches this way.
        let mut extent = f64::NEG_INFINITY;
        for i in 0..e.n {
            let el = u.element(ElementId(m.elem[i]));
            let reach = e.pos[i][0] * dir[0] + e.pos[i][1] * dir[1] + e.pos[i][2] * dir[2]
                + el.radius.get();
            if reach > extent {
                extent = reach;
            }
        }

        // Surface character: atoms within SHELL of the supporting plane,
        // weighted by how close they are to it. Fixed iteration order, so the
        // summation order is fixed (spec §13.1).
        let mut num = 0.0;
        let mut den = 0.0;
        for i in 0..e.n {
            let el = u.element(ElementId(m.elem[i]));
            let reach = e.pos[i][0] * dir[0] + e.pos[i][1] * dir[1] + e.pos[i][2] * dir[2]
                + el.radius.get();
            let w = (reach - (extent - SHELL)).max(0.0);
            num += w * el.affinity;
            den += w;
        }

        out.r[d] = extent;
        out.a[d] = if den > 0.0 { (num / den).clamp(-1.0, 1.0) } else { 0.0 };
    }
    out
}
```

### Task 10: The binding kernel

**Carried in from Task 4's review — `affinity` carries no drawn information and
its trend direction is fixed.** §7.1 line 288 says "the sign of each trend is
drawn from the seed, so one universe has affinity rising across a period and
another has it falling. This costs nothing and is the difference between
'invented' and 'renamed'." Measured over 500 universes: affinity falls across a
period in **1020 of 1020** cases, and `(k, units) -> affinity` has **0 bit
mismatches**, so no drawn constant enters the formula at all.

Separately, the attained range is **[0.140476, 1.000000]** — strictly positive,
exhaustively over the `(k, units)` grid. §8.3's charge term `-(a_A + a_B)^2` is
maximised at zero when the two affinities are *opposite*, so an all-positive
range degenerates it from a complementarity test into a monotone penalty on
total surface affinity, and §5's membrane mechanism — one flank positive, the
opposite negative — is unreachable.

How `a` is summed from element affinities is **this task's** code, so the remedy
may belong here rather than in Task 4: if the sum is centred or mean-subtracted,
the problem dissolves. What must not happen is the range being inherited by
default. `affinity_is_in_range_and_continuous` asserts the attained bounds on
both sides, so it fails loudly the moment either moves.

*Discriminator:* the attained affinity set reaching the binding kernel must
straddle zero over the enumerable `(k, units)` grid, and the test must assert the
attained range rather than containment in `[-1, 1]` — a containment assertion
passes for a collapse as well as for correctness, which is how the old
`> -1.0` bound sat with 1.14 of slack and could not fire.

```rust
//! Binding by shape complementarity (spec §8.3).
//!
//! One operation, reused at every scale: two molecules sticking together, an
//! enzyme recognising a substrate, a membrane self-assembling, a pore gating
//! passage. All of them are this function.
//!
//! At D = 42 and 60 rotations this is ~2,520 iterations per call, which is
//! affordable **only** because it is memoised per species pair (spec §8.6).
//! Nothing reachable from a simulation step may call it directly.

use crate::geodesic::{Geodesic, N_ROTATIONS};
use crate::signature::Signature;
use borbax_units::Thermal;
use borbax_universe::UniverseConsts;

#[derive(Debug, Clone, Copy, PartialEq)]
pub struct BindConsts {
    /// Extents of two fitting surfaces should sum to about this.
    pub ideal_gap: f64,
    pub w_shape: f64,
    pub w_charge: f64,
}

impl From<&UniverseConsts> for BindConsts {
    fn from(c: &UniverseConsts) -> Self {
        Self { ideal_gap: c.ideal_gap, w_shape: c.w_shape, w_charge: c.w_charge }
    }
}

/// Best complementarity score over all 60 relative orientations.
///
/// Higher is better; the maximum is 0, achieved by a perfect fit. The score is
/// a negated sum of squares, so it is always <= 0.
///
/// **The summation shape here is physics.** Two accumulators, `shape` and
/// `charge`, each summed in direction order, then combined once. Interleaving
/// them, or splitting either into multiple accumulators for speed, changes the
/// result bit-for-bit and moves every golden hash (spec §13.1).
#[must_use]
pub fn affinity<const D: usize>(
    a: &Signature<D>,
    b: &Signature<D>,
    g: &Geodesic<D>,
    k: &BindConsts,
) -> f64 {
    affinity_with_rotation(a, b, g, k).0
}

/// The score, plus which rotation achieved it.
///
/// The renderer needs the winning orientation (§14.5) and must not re-derive
/// it with its own loop: a second comparison written as `>=` instead of `>`
/// picks a different rotation on ties, and the diagram would then disagree
/// with the physics it is supposed to explain. One comparison, one answer.
#[must_use]
pub fn affinity_with_rotation<const D: usize>(
    a: &Signature<D>,
    b: &Signature<D>,
    g: &Geodesic<D>,
    k: &BindConsts,
) -> (f64, usize) {
    let mut best = (f64::NEG_INFINITY, 0usize);
    for r in 0..N_ROTATIONS {
        let perm = &g.perms[r];
        let mut shape = 0.0f64;
        let mut charge = 0.0f64;
        for i in 0..D {
            // `anti` is load-bearing and its omission is silent. Two bodies in
            // contact touch along *opposite* directions: A's surface reaching
            // along +d meets B's reaching along -d. Indexing `b` by `perm[i]`
            // directly compares A against B's point inversion.
            //
            // And because -I has determinant -1, it is not in the 60-element
            // rotation group — so dropping `anti` does not merely lose a term,
            // it converts this into a search over the 60 *improper* elements.
            // Reflections only, the exact opposite of §22.8, with nothing
            // failing to say so.
            let j = g.anti[perm[i] as usize] as usize;
            let ds = a.r[i] + b.r[j] - k.ideal_gap;
            let dc = a.a[i] + b.a[j];
            shape += ds * ds;
            charge += dc * dc;
        }
        let score = -(k.w_shape * shape + k.w_charge * charge);
        // Strict `>`: on a tie the lowest rotation index wins. Load-bearing —
        // the renderer reads this index (§13.1).
        if score > best.0 {
            best = (score, r);
        }
    }
    best
}

/// Symmetric by construction: the pair is ordered before evaluation.
///
/// `affinity` is symmetric mathematically — the permutation set is a group, so
/// it is closed under inverse, and the per-direction terms are symmetric in
/// their arguments. But the two orderings sum in different sequences, and
/// floating-point addition is not associative, so they can differ in the last
/// bits. Ordering the pair removes the question entirely rather than relying
/// on the difference staying below a threshold nobody is checking.
///
/// Every caller and the memo must use this, not `affinity`.
#[must_use]
pub fn affinity_ordered<const D: usize>(
    a: &Signature<D>,
    b: &Signature<D>,
    g: &Geodesic<D>,
    k: &BindConsts,
) -> f64 {
    match a.lex_cmp_pub(b) {
        std::cmp::Ordering::Greater => affinity(b, a, g, k),
        _ => affinity(a, b, g, k),
    }
}

/// Cheap rotation-invariant rejection, run before the full search.
///
/// Any rotation permutes the extents, so the *sorted* extents are invariant.
/// If the largest extent of one plus the smallest of the other already
/// overshoots the ideal gap by more than the tolerance, no orientation can
/// recover it. Conservative by design: it must never reject a pair the full
/// search would have liked, which `prefilter_never_rejects...` asserts.
#[must_use]
pub fn may_bind<const D: usize>(
    a: &Signature<D>,
    b: &Signature<D>,
    k: &BindConsts,
    threshold: f64,
) -> bool {
    // A genuine upper bound on `affinity`, not a heuristic.
    //
    // For any rotation, Σᵢ dsᵢ² ≥ D · mean(ds)² by Cauchy–Schwarz, and mean(ds)
    // is rotation-invariant because Σr is. The charge term is a sum of squares
    // and so is ≥ 0. Together those give a true ceiling on the best achievable
    // score, which means a rejection here provably could not have scored above
    // `threshold`.
    //
    // The previous version compared `best_case < ideal_gap * 2.0`, which was
    // not a bound on anything the search computes and took no threshold — so
    // "conservative" was not a statable property. Measured, it rejected 0.000%
    // of 20,000 random pairs: it filtered nothing while being unprovable,
    // which is the worst of both.
    let sum_a: f64 = a.r.iter().sum();
    let sum_b: f64 = b.r.iter().sum();
    let mean_defect = (sum_a + sum_b - D as f64 * k.ideal_gap) / D as f64;
    let ceiling = -(k.w_shape * D as f64 * mean_defect * mean_defect);
    ceiling >= threshold
}

/// Probability that a collision produces a bound complex.
///
/// A logistic in affinity over temperature. Written with `exp` deliberately
/// isolated here so that the vendored deterministic implementation has exactly
/// one call site to replace (spec §13.1).
#[must_use]
pub fn bind_probability(affinity: f64, t: Thermal, midpoint: f64) -> f64 {
    // `affinity` is a negated sum of squares and so is always ≤ 0, with 0 the
    // perfect fit. Without a midpoint the logistic saturates at 0.5 — a
    // perfect complement would bind half the time and nothing could ever bind
    // more readily than that. `midpoint` is the affinity at which binding is
    // even odds, and it comes from the universe rather than being a literal.
    let x = ((affinity - midpoint) / t.get().max(1e-6)).clamp(-40.0, 40.0);
    1.0 / (1.0 + borbax_units::det_math::exp(-x))
}
```
